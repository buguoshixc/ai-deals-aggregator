# 方案 B · 均衡（推荐）—— A 的全部 + 站内可爬结构 + 紧凑视图

**一句话**：在方案 A 的视觉层之上，补两件结构性的事：**每条优惠有自己的静态页**（可索引 URL 从 1 变 81）
与**紧凑行视图**（首屏从 9 条变 16+）。功能面只加零依赖、无后端的部分。

**适合谁**：想让站点「被搜到」并且「一屏看到更多」，但仍要保持零构建、单文件、不热链的约束。

---

| 指标 | 改前（实测） | 改后（目标） | 怎么测 |

| 同源内链 | **1 条** | ~140（卡片标题 → 站内详情页 + 面包屑 + 相关条目） | `study-site.js` 量产物 |

## 2. 具体做什么（＝ A 的全部 + 下列）

| 项 | 内容 | 关键决策 |
|---|---|---|
| **G1 独立详情页** | 构建期生成 `dist/deal/<id>/index.html`（仅 `type:"deal"`，当前 80 条） | **标题链接改为站内详情页，CTA「获取 →」仍指向厂商官网**（守住「落地页指向官方」；这是单行可回退的改动） |
| **G8 详情页 SEO** | 每页 `canonical`、`BreadcrumbList`、`ItemList`、`og:*`；`sitemap.xml` 由 1 条 → 81 条 | 全部由同一份 RENDER-CORE 纯函数产出（构建期与浏览器同一模板，不分叉） |
| **G2 紧凑行视图** | 卡片 ↔ 行 两态切换（记 localStorage）；行 = 厂商 logo + 标题 + 档位 + 优惠摘要 + 时间 + CTA，行高 44–48px | 默认仍是卡片（不改变现有用户的第一印象），紧凑为可选视图 |
| **G9 订阅** | `feed.xml` + `feed.json`，零依赖手写序列化（沿用 `og-image.js` 那种「用 Node 内置模块自己拼」的做法） | 只含 `type:"deal"` 且未过期 |
| **G10 纠错** | 卡片详情里加「信息有误 / 我核验过」链接 → GitHub Issue 模板（预填 id/title/url） | 无 JS 也成立（纯链接） |
| **G14 手机端** | 紧凑视图在 ≤760px 同样可用；触控目标 ≥44px；facets 横向滚动保持 | 断点沿用现有 760 / 1180 |

**架构约束（必须遵守）**：详情页也走 RENDER-CORE——构建期抽出纯函数区在 `vm` 沙箱求值，
浏览器端同一函数；任何在纯函数区引用 `document/window/state` 的写法会让构建直接失败（现有机制）。
预渲染标记从 6 个增加到 7 个（新增 `<!--PRERENDER:detail-->`），并登记进 `validate.js` 的标记清单。

## 3. 明确不做

- 不做收藏/对比（G11）、不做首页一级视图重排（G16）、不做英文站（G17）
- 不引入后端、账号、统计、任何外部请求；不改 `deals.json` 契约（详情页字段全部是派生）

## 5. 风险与对冲

| 风险 | 对冲 |
|---|---|
| 详情页 80 个文件推高产物体积与构建时间 | 先量：当前 `dist/` 326.9 KB / 构建约 1 秒级；预计新增 1.5–2.5 MB（每页 20–30KB）。若超预算，改为「只给未过期且带 `features`/`priceLine` 的条目建页」或共用一个详情页壳 + 客户端取数（但那会破坏「不执行 JS 也能读」的红线，故优先接受体积） |
| 标题改指站内、直达官方的点击数下降 | CTA 保留并加大（全宽实心按钮）；meta 行保留原文字链；上线后用 `verify --url` 冒烟确认两者都在 |
| 81 条 sitemap 与实际页面不一致 | 构建期断言集合相等（多余/缺失都失败） |
| 紧凑视图在长文案上裁切 | 复用现有「最后一个元素底边不越界」断言，两种视图各跑一遍 |
| 详情页与首页正文重复导致薄内容 | 每页主体是**该条目的完整字段**（原文 + 译文 + 有效期 + 适用条件 + 覆盖模型 + 来源署名），非首页摘要复制 |

## 6. 验收

```bash
npm test && npm run test:strict && npm run build && npm run verify
# 新增：详情页数 = 未过期 deal 数（80）；sitemap 条目 = 81；feed 可解析；紧凑视图首屏 ≥16
node scripts/serve.js --dir=dist   # 手工点开 /deal/<id>/ 与两种视图
npm run verify -- --url=<线上地址> # 部署后冒烟（需你另行确认部署）
```

**工作量**：大（A 的中等 + L×2 + M×1）。**风险等级**：中。**可回退性**：中（详情页可整目录删除；标题链接是单行改动）。
