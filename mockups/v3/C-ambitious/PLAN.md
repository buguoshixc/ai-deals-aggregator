# 方案 C · 进取 —— B 的全部 + 收藏对比 + 首页按意图重排 + 英文覆盖

**一句话**：把站点从「一个列表 + 一个筛选条」升级成「按意图切的一级视图」，
补上用户留存类功能（收藏/对比），并开出英文入口。**唯一一套会引入持续人工成本的方案**。

**适合谁**：打算把这个站当作长期产品做，愿意在每个新增条目上继续投入人工（译文、分类判断）。

---

## 1. 目标指标（＝ B 的全部 + 下列）

| 指标 | 改前（实测） | 改后（目标） | 怎么测 |
|---|---|---|---|
| 一级视图 | 1 个（列表 + facet + 「全部工具」Tab） | 5 个意图入口：**免费额度 / 学生·教育 / 国内厂商 / 全部工具 / 全部优惠** | 断言每个入口可达且预渲染有正文 |

| 方案 B 的全部指标 | — | 同 B | 同 B |

## 2. 具体做什么（＝ B 的全部 + 下列）

| 项 | 内容 | 关键决策 |
|---|---|---|
| **G16 首页 IA 重排** | 顶部从「搜索 + facet 条」扩展为**一级意图入口**（免费额度 / 学生·教育 / 国内厂商 / 全部工具 / 全部优惠），每个入口是**独立的预渲染视图**（同一份 URL + query 或 hash，或独立静态路径二选一，见风险） | 排序与分档逻辑不变（仍是力度五档 + 即将截止），只换「入口的粒度」 |
| **G11 收藏 / 对比** | 卡片上加收藏与「加入对比」；对比视图并排 2–4 条关键字段（额度、适用条件、有效期、价格阶梯、核验状态） | 纯 `localStorage` + `URLSearchParams`；**无 JS 时这两个按钮不渲染**（沿用「没有 JS 就不给可点暗示」的既有做法） |
| **G17 英文覆盖** | `/en/` 首页 + `/en/deal/<id>/` 详情页；译文沿用 `zh` 覆盖层的**同一套机制反向复用**（新增 `scripts/data/translations_en.json` + `en` 字段 + 指纹校验） | 只翻译 `type:"deal"` 与首页静态文案；**不翻译厂商名与模型名**（专有名词不动） |

## 3. 明确不做

- 不做后端 / 账号 / 云端同步收藏（只用 localStorage）
- 不做用户提交优惠（那会引入审核与信任成本，与「人工核验」的现有节奏冲突）
- 不做统计与 A/B（红线：无外部请求）
- 不引入任何前端框架或构建工具（仍是零构建单文件 + 构建期预渲染）

## 5. 风险与对冲

| 风险 | 对冲 |
|---|---|
| **英文覆盖是持续成本，不是一次性成本** | 每个新条目都需要人工英文译文；建议先只做首页与 20 条高价值条目，其余英文页回退中文（并在页面上如实标注）——**不做机器翻译**，与现有 `zh` 的红线一致 |
| 首页一级视图可能让「默认视图」反而变复杂 | 默认仍落在「全部优惠 + 力度分档」；一级入口是**快捷方式**而非新层级；mockup 先看效果再实施 |
| 一级视图用 query/hash 会削弱 SEO（同一 URL 多变体） | 优先**独立静态路径**（`/free/`、`/student/`、`/cn/`），各自 canonical，避免 query 变体稀释权重 |
| 收藏/对比增加 JS 复杂度，可能拖慢首屏 | 交互在首屏渲染完成后绑定（现有做法）；`verify` 断言首屏 LCP 相关不存在退化（卡片数、无外部请求、无控制台错误不变） |
| 对比字段缺失（`priceLine` 只有 3 条、`features` 31 条）导致对比表大面积空白 | 对比表**只展示有值的字段**，缺值不占位、不显示「暂无数据」噪音（与诚实性红线一致） |

## 6. 验收

```bash
npm test && npm run test:strict && npm run build && npm run verify
# 一级视图 5 个入口各有预渲染正文；/en/ 与 /deal/<id>/ 互指 hreflang
# 收藏/对比：无 JS 时按钮不渲染；URL 分享后选择可复现
# 方案 A/B 的全部断言依然通过
```

**工作量**：很大（B + L×2 + M×1）。**风险等级**：中高。**可回退性**：中（英文目录与一级视图可整块移除；收藏/对比是增量代码）。
