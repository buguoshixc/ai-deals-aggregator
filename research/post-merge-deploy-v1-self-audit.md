## 2. 本轮**没有**证明的东西（与报告 §5 同源，这里只列自审视角）

1. **14 条 ≠ 全站**：产物 304 个文件（186 页），未抽到的路由未被覆盖；「线上 == 本地」只对这 14 条成立。
2. **单边缘、单时刻**：没有多点/多时刻采样 ⇒ 「所有边缘都已一致」未证明；`x-cache: MISS` 只说明**这一次**
   是现取源站。
3. **单出口区域**：没有换出口/DNS 复测 ⇒ 区域差异未证明（报告 §5.3）。
4. **master 在复核期间又前进了两次**（`557095875f`、`4ecfb9db`）⇒ 本轮证明的是
   「**被复核提交的那次部署** == 它的本地构建」，不是「当前头的部署已就位」。
5. **两次构建一致 ≠ 跨环境一致**：同机同版本，未做跨平台/跨 Node 比较。
6. **内容正确性不由本复核承担**：逐字节相同只回答「是不是这一版字节」。
7. **`_notes.ndjson` 的语义对账**（清单 ↔ 页面逐条）不在本射程。

## 3. 装置与口径（记下来，免得下一轮重踩）

1. **任务书 Verify 里的 `node scripts/tree-digest.cjs dist` 在本仓不存在**（`Test-Path` = false）。
   本轮用的是前几轮同一份 Tier-3 摘要器 `.arch-v1/tree-digest.cjs`（逐文件 sha256 + 全树摘要 + 清单摘要），
   算法与 t1/t6 一致；这一点写进了证据的 `build-digest.json.digestTool`。
2. **第二次构建用 `npm run build -- --out=dist.b2`**：同一条构建路径、不同输出目录 ——
   这样两次构建都能留下来对比（直接连跑两次 `npm run build` 会覆盖 `dist/`，就没有可比的两份了）。
3. **`--out` 的产物目录不进 git**：`dist.b2/` 与 `dist/` 一样属于过程产物，本轮没有把任何产物入库。
4. **判据复用 t1 的三不变量 + 逐字节判据**，而不是新写一套：这样两轮读数可以直接对着看
   （t1 的 `/plans/coding/` = `2f593e8742a2d560`，本轮仍是同一个值）。
5. **非 200 / 不同的处置口径**已写死在报告 §4：先报、原样记录、不归因、不用重试掩盖；
   上一轮的 503 瞬态按同一口径登记（正文未留存、成因未归因），本轮**不重复调查**。

## 4. 自评结论

* 三条验收都有现场读数支撑：**304 文件 + 两次构建逐字节一致** · **14/14 逐字节相同（含 `_notes.ndjson`）**
  · **三不变量全绿**；本轮**没有**出现需要走「异常分支」的读数（0 条非 200、0 条不同）。

  与 `d19017af` 的本地构建逐字节相同**；超出这个窗口、这些路由、这个出口的事，本复核不说话。
