# t35 / M24 边界：引文验真到底有没有门禁（如实入档，可直接引用）

> 用途：t21 self-audit、t20 最终报告、t34 残余登记表可直接引用下文（t34 的登记表由队长转交，本文件不改它）。
> 结论一句话：**`provenance-selftest` 与新增的自称牙覆盖的是"规则与形态"，不是"这段文字真的在官方页上"。**

## 一、实测事实（t17 独立实验 + 本轮复核）

把 `deals.json` 里真实记录 `4987c183fc1a`（360智脑开放平台，1 条引文）的 `evidence[0].quote`
改成**编造文本**后：

- `provenance-selftest` 仍然 **114/114 全绿**（当轮项数；本轮加牙后为 132 项，同样不含"引文是否忠于官方页"的判据）；
- 其它任何第三方离线门禁也不会发现（`validate --strict` / `build-local` / `verify-site` 都不比对官方页原文）。

原因不是"门禁写错了"，而是**离线状态下无法回答这个问题**：要回答它必须联网重取官方页、再逐字比对，
那是**审查**（人来判断，或带网络的取证流程）的工作，不是确定性门禁的工作。
把"改写成编造文本"与"引文合法"分开的那条线，靠的是下面三层，**没有第四层**。

## 二、真实引文验真由三层覆盖（缺一层都不算覆盖）

| 层 | 覆盖什么 | 机制 | 实测 |
| --- | --- | --- | --- |
| (a) 抄件**逐字耦合** | 关系层里"复制的引文"不许新造 | `model-registry-links.json` 的 `_rules ⑥`：链接里的每条引文必须与**被引用记录自己的**引文 `field/sourceUrl/quote` 逐字相同；`validateLinks()` 判红 | API 侧 59 条抄件与记录逐字一致（t33 复核：不一致 0） |
| (b) **独立审查** | 盘上引文是否真忠于官方页 | 逐条打开官方页与 `quote` 对照（t15 的做法），并把"改写件"当 finding 处理 | t15 抓到 4 条改写件（F1/F2）→ t33 改成官方逐字片段（commit `af92d5d`） |
| (c) **自称牙**（t35 新增） | "改写件**自称**逐字"这一种形态 | `validate --strict` 的 `checkProvenanceGuard()` ④：13 篇文件里全部 `quote` 不许出现元自称（逐字 / 一字不差 / 原文照录 / 原样照录 / 照抄 / 原文如此 / verbatim / word-for-word）；命中即红并点名字段路径 | 盘面 **292 条 quote / 13 篇文件 · 0 命中**（今天不误伤）；注入「（逐字）」⇒ 必红（`research/_raw/t35/inject-selfclaim-counter.cjs`） |

**不许写成结论的说法**：「真实引文已逐条验真」（假的）、「引文全部与官方页一致」（假的）、
「0 命中 ⇒ 引文都是真的」（0 命中只说明**没有自称**）。

## 三、自称牙的判据边界（判不准的词不写成牙）

- **纳入**（唯一功能就是声明"引用行为本身"）：逐字 / 逐字逐句 / 一字不差 / 原文照录 / 原样照录 / 照抄 /
  原文如此 / verbatim / word-for-word。落在 `quote` 里就是 F1/F2 那个措辞（实例：`（Developer 档逐字）`，
  见 commit `af92d5d` 的 `-` 行）。
- **不纳入**：「官方原文」「官方原话」——它们**可能是官方页自己的内容**（引用一段谈"以官方原文为准"的
  公告是合法的）。判不准的词写成牙，只会逼后来者放宽整条判据。扫描器里这两条保留为"待裁决"读数。
- **不在射程内**：F1/F2 的另一半形态 —— **编辑性括注进了引文正文**（如 `（官方 Supported Models 页…）`）。
  它需要人读才能判，属 (a)+(b) 覆盖；本轮**没有**把它做成牙，也不假装覆盖了。
- 牙的语义是"**要求人看一次**"：命中 ≠ 证明改写，而是"引文里出现了不该由引文自己说的话"。
