② Stable event id（派生字段）
  ✓ 同一条事件两次计算 ⇒ 同一个 eventId
  ✓ 值不同 ⇒ eventId 不同
  ✓ 日期不同 ⇒ eventId 不同
  ✓ 事件落库时带上重算得到的 eventId
  ✓ 手写 eventId ⇒ verifyStore 红

③ 价格：涨价 / 降价 / 活动价开始结束换挡
  ✓ 正常价格 99 → 68 ⇒ 恰好一条 price_changed
  ✓ 价格事件的 from / to 是数字（不是字符串）
  ✓ 改价后 verifyStore 通过
  ✓ promoPrice null → 9.9 ⇒ promo_started（牙 5）
  ✓ promo_started 事件带 from=null / to=9.9
  ✓ promoPrice 9.9 → null ⇒ promo_ended
  ✓ promoPrice 9.9 → 19.9 ⇒ promo_changed（不是 started / ended）
  ✓ 币种变化 ⇒ billing_changed（不做汇率，只如实记）

④ 额度：增加 / 减少 / 口径变化
  ✓ 额度 6000000000 → 3000000000 ⇒ quota_decreased（牙 4）
  ✓ quota_decreased 带 from / to 数值
  ✓ 额度 3000000000 → 6000000000 ⇒ quota_increased
  ✓ 固定额度 → 限速（amount 变 null）⇒ 只能是 quota_changed，不谎称增减
  ✓ 额度类型变化 ⇒ quota.type 记 quota_changed
  ✓ 跨量纲的数值同时变化时**不**比大小（quota.amount 也是 quota_changed）
  ✓ 跨量纲时不出现 quota_increased / quota_decreased
  ✓ 额度刷新周期变化 ⇒ quota_changed
  ✓ 限速型额度说明只差尾随空格 ⇒ 0 事件
  ✓ 限速型额度说明实质变化 ⇒ 一条 quota_changed
  ✓ 量化型套餐的 quota.description 文案变化 ⇒ 0 事件

⑤ 模型：新增 / 移除 / 顺序（牙 1）
  ✓ 新增一个模型 ⇒ 一条 model_added（from = null）
  ✓ model_added 的 to 是模型对象
  ✓ 移除一个模型 ⇒ 一条 model_removed（to = null）
  ✓ supportedModels 只是顺序变化 ⇒ **0 事件**（牙 1）
  ✓ 顺序变化的输入仍能通过一致性校验（顺序不是变化）
  ✓ 同名模型 role 变化 ⇒ model_changed（不是增删）
  ✓ 模型 note 只差标点与空白 ⇒ 0 事件

⑥ 限制条件与销售地区
  ✓ 新增限制条件 ⇒ 一条 restriction_changed（from/to 是整个数组）
  ✓ 限制条件 note 只差标点 ⇒ 0 事件
  ✓ 销售地区 国内 → 国外 ⇒ availability_changed

⑦ 幂等：重复运行不重复产生事件（牙 3）
  ✓ 第一次运行产生一条 price_changed
  ✓ 连续第二次运行 ⇒ 0 条新事件（牙 3）
  ✓ 连续两次运行的事件总数仍为 1
  ✓ 无事件发生的运行字节不变
  ✓ 重复运行后 verifyStore 仍通过
  ✓ 连续 30 次变化 ⇒ 30 条事件（链式）
  ✓ 30 条链式事件后 verifyStore 通过

⑧ 退出保护：一次没见到不算下线 / 批量熔断（牙 2）
  ✓ 第一次未见 ⇒ **0 条 ended**（R2：一次没采到不算下线）
  ✓ 第一次未见只推进观测态（misses=1，未 ended）
  ✓ 观测期未满时 verifyStore 仍通过（合法的中间态）
  ✓ 连续第二次未见 ⇒ 一条 ended(source_no_longer_lists)
  ✓ ended 带墓碑标签（记录离开数据后还能认出是谁）
  ✓ ended 后 verifyStore 通过
  ✓ 一次删掉 3/4 条套餐 ⇒ **0 条 ended**（牙 2 批量熔断）
  ✓ 熔断只留档：anomalies 有记录且列出缺席套餐
  ✓ 熔断时观测态标成 blockedAt（解释为什么没记 ended）
  ✓ 熔断状态下 verifyStore 通过（数据与日志仍然自洽）
  ✓ 熔断不推进计数（misses 仍是 0）
  ✓ 本次输出为空 ⇒ 0 条 ended（empty_dataset）
  ✓ 空输出时 verifyStore 通过
  ✓ 本次运行输入不可信 ⇒ 0 条 ended、不推进计数
  ✓ 输入不可信时 verifyStore 通过
  ✓ 缺席的套餐回来 ⇒ 观测态清零、0 事件
  ✓ 恢复后 verifyStore 通过
  ✓ --allow-mass-removal ⇒ 缺席的 3 条各记一条 ended(withdrawn)
  ✓ --allow-mass-removal ⇒ anomalies 标 override
  ✓ 放行批量下架后 verifyStore 通过

⑨ 重现（restore）与字段追赶
