## 3. Filter

六个维度，全部 AND；每个维度**单选**，再点一次即取消：

| 维度 | 控件 | 选项（本期） | 规则 |
|---|---|---|---|
| 平台 | chips | 8 个 | 全等 |
| 额度类型 | chips | 积分 6 / 按窗口限速 1 / 其他 2 | 全等 |
| 地区 | chips | 国内 7 / 国外 2 | 全等（数据的 `region` 字段，**不**宣称"大陆可用") |
| 是否有活动价 | chips | 有 2 / 无 7 | 二分且互补 |
| 模型 | select | 10 个模型名 + **「模型未标注」6 条** | 精确命中；`__none` = `supportedModels` 为 null |
| 正常月费 | select | `¥0–49` 2 / `¥50–99` 4 / `$10–19` 1 / `$20–29` 1 | **同币种 + 同周期 + 半开区间**；原价未标注 / 非月付不入选 |

- **价格区间不跨币种**：选项标签自带币种（如「¥50–99（CNY）」）。没有汇率就不用假汇率 ——
  这是 `NEXT-STEPS` 里写的"同币种价格区间筛选"的落地方式。
- **阶梯是声明式常量**（`PRICE_LADDER`，本页唯一的任意值）：`CNY:[0,50,100,200]`、
  `USD/HKD/EUR/GBP:[0,10,20,50]`、`SGD:[0,10,50,100]`、`JPY:[0,1000,3000,10000]`；
  末档开区间；只对存在的币种生成，**只保留真有命中的档位**（零计数入口不渲染）。
- 计数语义与首页一致：**按钮上的数字 = 点下去会看到多少条**（其余维度保持当前状态）。
- **不生成 URL**：状态只活在内存里，`location.search` 始终为空（真浏览器断言）。

## 4. Sort

| 档位 | 默认方向 | 键 | 不可比较的怎么办 |
|---|---|---|---|
| 默认顺序 | — | `index`（规范序） | 无（全序） |
| 正常月费 | 升序 | `billing.regularPrice` | `null`（原价未标注）**排在可比较项之后** |
| 活动价 | 升序 | `billing.promoPrice` | `null`（没有活动价）同上 |
| 名义 Token 单价 | 升序 | `derivedMetrics.nominalUnitPrice` | 算不出的一律同上；**且这一档只在真有可比行时才出现** |
| 最近更新 | **降序** | `lastSeen` | 无（每条都有） |

三条不可让步的性质（每条都有离线 + 真浏览器断言）：

1. **`null` 恒在可比较项之后，`asc` / `desc` 都不越过它**。把"没有这个数据"的套餐翻一下方向
   顶到"最便宜"的位置上，是这一页最容易犯、也最坏的错。
2. **价格排序与单价排序都按币种分组**（组序 = 该币种在规范序里首次出现的位置），
   **`dir` 反转也不互换组序**。`¥99` 与 `$20` 之间没有大小关系。
3. **恒为全序且稳定**（平局按规范序 `index`），所以"再点一次"不会得到第三种顺序。

## 5. Mobile

**只选一个方案**：**横向滚动 + 前两列固定**（题面 §八 的四选一），全程只有一张表、一套数据模板
（真浏览器断言 `document.querySelectorAll('.ptable').length === 1`）。

- ≤760px：`平台` sticky `left:0`（定宽 6.5em，允许换行）、`套餐` sticky `left:6.5em`（`max-width` + `overflow-wrap`），
  `thead` 同名列一起 sticky，两列用不透明底色 + 1px `box-shadow` 接缝。
- 筛选 chip 在窄屏收成**一行横滑**（与首页 `.facetsin` 同一条既有做法）：实测表格起点
  从 716px 提到 **616px**（控件区少了 100px）。
- 实测：390 / 360px **页面级横向溢出 0px**（筛选生效 + 详情展开时同样 0）；
  横滚 300px 后平台列 `left=16`（容器 16）、套餐列 `left=94`，粘性列里的官方链接仍是
  `elementFromPoint` 命中的**最上层元素**（可点）。
- **两处实测发现**（都写进了 CSS 注释，不留假规则）：
  ① `.ptable` 自带的 `overflow:hidden`（桌面圆角裁剪）会成为"最近的可滚动祖先" ⇒ 粘性失效
  （修复前首列 `left=-283px`）；窄屏置 `overflow: visible`，圆角交给外层。
  ② 详情行 `colspan=11` 比滚动视口宽，粘性无法同时满足两个方向的约束 ⇒ **详情行刻意不粘**。

## 7. Token 单价口径

- 计算与否**完全沿用 v2.1 的判据**（五个条件 + 一个补丁）；本阶段**没有改一个字节**。
- 页面口径（`PLAN_WORDING.nominalUnitPriceNote`）原样保留：
  **「名义 Token 单价只根据套餐标称额度折算，用于粗略比较，不代表不同模型 Token 的实际价值相同。」**
- 渲染层与交互层的**双重 fail-closed**：`planRowOf` 与 `planCompareRowOf` 都只在
  `quota.type === 'tokens'` 时才承认 `derivedMetrics.nominalUnitPrice`。数据层已经保证过这件事，
  这两处挡的是"数据被绕过"的那一种 —— 把积分 / 限速 / 用量池显示成一个 Token 单价，
  是这一页最坏的错，而它现在只差一个 JSON 字段的距离。
- 页面上**不许出现的结论性词汇**只有一个出处（`FORBIDDEN_CLAIM_WORDS`：性价比 / 最划算 /
  最超值 / 最值得买 / 值得买 / 排行榜 / 排行 / 综合评分 / 星级 / 推荐指数 / TOP 1 / TOP1 /
  第一名 / 最优选），三处查同一份清单：构建期内存、产物自检**从磁盘回读**、真浏览器 `innerText`；
  数据层（套餐名 / 备注 / 额度口径 / **搜索串（含平台别名）**）另查一遍。
- **本期的真实数字**：9 条套餐里可计算 **0 条**（额度类型是积分 6 / 其他 2 / 按窗口限速 1，
  没有任何一家官方页给出固定 Token 额度）。因此那一列全是 `—`，
  且**"名义 Token 单价"这一档排序不出现在页面上**（与"零计数入口不渲染"同一条纪律），
  改为一句事实说明：「本期没有一条套餐的额度是固定 Token，名义 Token 单价与它的排序不适用。」

## 14. 上线后修复：口径说明被压成窄柱（2026-10-01）

**现象**（线上截图反馈）：页面底部「口径与说明」整段只占正文左侧约 1/3，
每句话被切在词中间（「…本页照原样列 / 出，不互相换算」），右侧留一条大空白。

**原因**：我在这一页给长文段写了 `max-width: 82ch`（"长文段 70~82ch 更好读"的习惯写法）。
`ch` 量的是 `0` 的宽度 —— 12px 字体下约 6.5px，**82ch ≈ 530px**；而 `.wrap` 正文容器是 1400px。
于是"可读性上限"在宽屏上变成了"一条窄柱"。**位置就在页脚，是读者理解这一页判据的唯一出处**，
属于最不该收窄的那类文本。

**修法**：`.plist` 与末尾 `.snote` 改为 `max-width: none`（宽度跟随正文容器），
并在 CSS 里写明这次踩坑的原因（防止下一个人"照着习惯"再加回来）。

**实测（真浏览器，同一份产物）**

| 指标 | 修复前（强制 82ch） | 修复后 |
|---|---|---|
| `.plist` 宽度 / 表格宽度 | 530px / 1380px | **1380px / 1380px** |
| 末尾 `.snote` 宽度 | 530px | **1380px** |
| 每句占几行（1440px） | `[2 2 3 1 1 2 3 3 2]` 最多 3 行 | **`[1 1 1 1 1 1 1 1 1]` 每句 1 行** |
| 390px 移动端 | 无变化（容器 358px 本就窄于 530px） | 无变化，页面溢出 0px |

**回归保护**：`verify-site.js` §19 新增两条断言（挂在既有步骤里，**没有新增门禁步骤**）——
① 列表与末尾段盒子宽度 ≈ 表格宽度（同一条正文容器）；② 每句 ≤ 2 行。
② 不是冗余：只量盒子宽度的话，"盒子很宽但每行只写一半就换行"仍然能绿；
而把 82ch 加回来时 ② 立刻变红（实测 3 行）。
