### 1.2 与任务书声称值的差异：`output` 覆盖写成了 108，实测 107

- 任务书 `API_COST_CALCULATOR_PROMPT.md:40` 写的是 `| input · output | **107 / 108（99%）** |`（读作 input 107、output 108）。
- 实测：`rates.output === null` 的条目**恰好 1 条**，就是 `openai/gpt-live-1/standard`
  —— 它按分钟计价（`mediaRates: [{kind:'audio', price:0.05, unit:'per_minute'}]`），
  **`input` 与 `output` 两个价都是 `null`**，不是「input 缺、output 有」。
  ⇒ **真实覆盖是 `input 107/108` + `output 107/108`**。

### 1.3 一处读法纠正：`channel` 是**计划级**，不在 `models[]` 上

任务书 §2 的「关键字段形状」把 `channel ∈ standard | off_peak | batch` 与 `pricing.*` 一起写在**计划级**那三行注释里，
但紧接着的第 9 条规则写「`channel`：9 条非 standard（`off_peak` 3 + `batch` 6）」——那两个数字是**条目级**计数，
容易让人以为 `channel` 挂在 `models[]` 上。实测：

- `plans[].channel` 有值；**`models[]` 上带 `channel` 键的条目 = 0**（重算见 §1.1 的命令）。
- 因此「3 + 6 = 9」是**条目级**（99 / 3 / 6，共 108 条）；**计划级**是 `off_peak` **2 条** + `batch` **1 条**（`standard` 21 条，共 24 条）。
- 源码侧同一条口径：`scripts/lib/api-cost-page.js:133` 从 `plan.channel` 收通道集合；
  `scripts/lib/api-cost.js:395` 用 `plan.channel !== channel` 过滤 —— 两处都读计划级。

引用「9 条非 standard」时必须写明是**条目级**，否则一复核就会对不上（与 D2 同一类坑）。

## 8. 边界与已知限制

1. **计算器是「出数机器」，不是顾问** —— 没有排序、没有推荐、没有性价比、没有「谁更便宜」。
   多模型同屏比较**不在本版范围内**（§7 第 3 条），这不是遗漏，是红线。
