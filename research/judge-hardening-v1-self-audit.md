## 1. 我可能弄错的五件事

### 1.1 「8 条修到会响」里，有两条的**首次**读数是被污染的（已查实）

- **R9**：`attack-matrix` 里那条 attack 用的是「改写**已登记规则内部**」的旧注入形态
  ⇒ 把 §19 隔离牙的锚点 `.pdetailbody { max-width: 72ch; margin-inline: auto; }` 改掉
  ⇒ 报「锚点出现 0 次 ⇒ 按红处理」。**这条红不是 `!important` 引起的**：干净形态
  （新增一条**独立规则** `.pdetailbody { max-width: 72ch !important; }`）⇒ **881/0 全绿** ✓。
- **V3**：`attack-matrix` 里那条 attack 注入的是 `need/free-api/` = **M15 的变异靶页**
  ⇒ 红在 M15 的控制组上。干净形态（注入 `plans/`，t5 原形态）⇒ 12 条 `note-clipped` ✓。

**结论**：这两条的「修复后」读数**不能**引用 attack-matrix 那两行，只能引用 §3/§4 的干净形态。
`research/_raw/judge-hardening-v1/attack-matrix.json` 里对这两行留了 `injectionNote` 字段说明。

### 1.2 竖直裁切第一版是**假绿**（我自己的 bug，不是判据没牙）

第一版只往 note 的 `box()` 加了 `scrollH/clientH`，**没有**加前置条件要用的
`overflowY` / `heightStyle` ⇒ `clipPossible` 恒为 `false` ⇒ 竖直分支永不触发，
前两轮探针都是「0 码」。当时的读数**看起来像「这条判据没牙」**，实际是**判据没数据**。
补上两个量之后才有 §4 的三条读数。**教训已写进报告 §6.4。**

### 1.3 「误报面 0」这句话的强度

我说的「1440/1600/760/360 四档误报 0 页」依据是：加完判据后 `--dir=dist` 是 **881/0**，
而 §22c 的四档确实都在同一轮里跑（@1440/@1600 全站逐条、@760/@360 样本集 29 页）。
**它没有证明**的问题：样本集只有 29 页（@760/@360 不是全站），
所以「窄屏档全站无误报」这句话**没有证据**——只能说「29 页样本集 + 全站两档」无误报。

### 1.4 「§19 逐条」的覆盖面

逐条遍历的是 **`WIDE_NARROW_ENTRIES`**（登记表），不是「产物里所有 ch 窄列」。
产物里**未登记**的 ch 窄列由 §22c ⑥ `narrow-unregistered` 咬 —— 两条合起来才完整；
单独拿 §19 说「所有窄列都被量了」是**夸大**。

### 1.5 生效宽 ±20% 的阈值是从**一条**登记项标定的

t17 的标定：全站只有 1 条 ch 声明，比值 1.000 ⇒ ±20% 零假阳性。
**这是单点标定**：第二条登记项（不同字体 / 不同字号 / 带 padding 的容器）进来时，
比值可能天然偏离 1.0（例如 `box-sizing` 与 `ch` 的基准差），那时 0.8–1.2 可能要重标。
报告 §7.1 已如实登记。
