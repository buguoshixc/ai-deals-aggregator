## 1. 我可能弄错的五件事（逐条反证或写清边界）

### 1.1 探针拷贝与原件是不是同一份代码？行号能不能通用？

* `.arch-v1/mk-probe.cjs` 每次拷贝后打印 `原文件未被写入：true`（读回来与拷贝前逐字节相同）；
  拷贝文件与 `scripts/tools/verify-site.js` **都是 9141 行**，改动只有 `ROOT` 一行与 5 个 `require` 的路径。
* 崩溃定位（`TypeError … 'filter'`）我**读了拷贝的那几行**（`wideNoteRowsByViewport` 只建 1440/1600 两个键、
  循环遍历 `WIDE_DESKTOP_VIEWPORTS`）—— 因为行号一致，报告里引的 `verify-site.js:7549–7557` 可直接核对。
* **边界**：`w950add` 的崩溃是**我改的拷贝**崩，不是原生支持三档；我没有把三档改到能跑（那要改 `scripts/**`）。

### 1.2 我自写的 DOM 探针，口径真的和真门禁一致吗？

它逐字镜像了 `contentBoxOf` / `bearsText` / `laysOutLines` / Range 字迹盒 / 合并轴（垂直或水平重叠 50%）/
阈值 `0.85 × min(主数据区, 页面列宽)` / 物理前置条件（现场 70ch）。
**一处部分校准**：形态 D 我量到 `textWidth 192px`、列 1 —— 与 t5 报告里同一形态的 `内容盒 192/107px` 吻合；
「已知缺陷 ⇒ ① 响」这一侧因此有对照。
**没有校准的一侧**：形态 F（我的反例）**没有真门禁读数对照** ——
我说它「零码」的依据是「① 的判据量 1380 ≥ 阈值 1173、② 的列数 1」，而不是「真门禁跑过这份注入」。
它是不是真的零码，取决于真门禁里 ① 的 `textWidth` 取值是否与我一致（我取「最窄承载块的 content box」）。
**建议**：把形态 F 交给下一轮真正改 `verify-site.js` 的那一轮，作为**必跑夹具**（我把它写进了建议 2）。

### 1.3 `w950` 的那 1 项失败，会不会掩盖了页面级判据？

不会：我核过失败项的**名字**（`§22c M10 变异后复测必须出现「note-narrow」违规码…`）与读数
（`盒 910px / 有字区域 899px · 视口 950`），并且 `metrics.layoutViolations` 里**有违规码的页数 = 0**。
⇒ 950 档本身没有让任何真实页面变红。**边界**：这只说明「按现有判据，950 档今天 0 码」，
不说明「950 档永远不会红」—— 那正是补这一档的意义。

### 1.4 时间读数的可信度

四个模式是**顺序**跑的 wall-clock（含浏览器启动、变异牙、186 页导航）：137.4 / 141.2 / 170.0 / 174.9 s。
两次增量不一致（29→63 页 +32.6 s；29→186 页 +37.5 s），说明**不是线性模型** ——
我在报告里只把它们当「同一量级的上界读数」，并写明了这个不一致，没有拿它们外推「一档 = X 秒」的精确值。
（真正落地时的成本应当在那一次任务里**实测**。）

### 1.5 采样集与覆盖数字是解析出来的，不是门禁直接给的

`29 / 63 / 13 / 50` 这些数来自我解析门禁自己的 check detail（样本集路由列表）与 `metrics.layoutNotes`（63 个 route）。
**交叉核对**：解析出的页数与检查**名字**里的数字一致（29 与 63 都吻合）✓。
**边界**：`layoutNotes` 是**条级容器**（271 条 / 63 页）——「有说明的页」按它定义；
若将来「有说明」的口径变了（例如条级容器改口径），这里的 63 要跟着重算。

5. **没有做「真出现竖排设计面时判据怎么改」的设计**（只给了检测信号）。
6. **没有跑 Full Gate**；基线对照是我自己的 `base` 拷贝（`880 项 / 0 失败`）。
