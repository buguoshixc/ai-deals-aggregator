## 二、新增字段

### 2.1 `audience` —— 适用人群（数组）

`["student","developer"]` 是合法且常见的取值（GitHub Student Developer Pack 就是）。
枚举：`student` · `developer` · `educator` · `education` · `general` · `other`。

- `educator`（教师）与 `student` **刻意分开**：合并会让「教师免费」与「学生免费」看起来是同一件事。
- `general` 的含义是**来源明说面向所有用户**，不是「我们不知道它面向谁」；后者是缺席。

### 2.2 `benefitType` —— 福利类型（数组）

枚举：`free_subscription` · `free_credits` · `free_api` · `free_model` · `discount` ·
`trial` · `student_plan` · `developer_credit` · `other`。

数组而非单值：一条优惠常常同时是「免费额度」与「免费 API」（阿里云百炼就是）。

### 2.3 `eligibilityDetail` —— 资格门槛（三态映射）

`studentRequired` · `educationEmailRequired` · `identityVerificationRequired` · `newUserOnly`

### 2.4 `claimRequirements` —— 领取要求（三态映射）

`creditCardRequired` · `manualApplication` · `accountRequired`

### 2.5 `availability` —— 中国大陆可用性

`chinaUsable`（三态）+ `regionRestriction`（来源写明的地区限制**原文摘要**，≤120 字）

与既有 `region` 的关系：`region` 说的是「这条优惠来自国内还是国外来源」，
`chinaUsable` 说的是「国内用户能不能用」。**`region: "cn"` 不构成 `chinaUsable: true` 的证据。**

### 2.6 `provenance` —— 「这条断言是谁说的」

```jsonc
"provenance": {
  "credibility": "editorial",          // editorial > curated > collected
  "sourceUrl": "https://…",            // 断言所依据的官方页
  "verifiedAt": "2026-09-22",          // 人工回访日期（仅 editorial/curated）
  "fields": { "availability": { "basis": "inferred", "derived": "inferred", "note": "…推断链…" } },
  "contrib": { "availability": ["curated", "collected"] }   // 逐字段贡献者记账（审计用）
}
```

- **逐字段**声明依据，不是一个整条标记：真实数据里「人群是官方页写的、中国可用性是从
  条款推的」这种混合来源很常见，整条级标记说不清它。
- `basis`：`source` / `documented` / `inferred`；**声明为推断（`basis` 或 `derived`）必须带
  `note`** —— 推断链就是断言的一部分，写不下来就说明它不该被当成结论。
- `contrib` 是「整条可信度」的唯一落点（见第五节）。

## 四、unknown 语义

**没有证据 ≠ false。** 这是本阶段的立身之本，落地成三层：

1. **数据层**：三态只接受 `true` / `false` / 字符串 `"unknown"`。用**字符串**而不是 `null`，
   是因为 `null` 与「字段没写」在 JSON 里长得一样，三态会在一次序列化往返后消失，
   而这两件事在页面上后果相反（「不用学生认证」可以立刻去领，「还没确认」得先去看官方页）。
2. **措辞层**：`true`/`false`/`unknown` → 「是」/「否」/**「尚未确认」**，
   由 `lib/audience.js` 的 `triLabel()` **单一出处**给出。
3. **渲染层**：`unknown` 的单个键**不出行**（它是「我们没查到」，不是信息）；
   唯一例外是 `chinaUsable: 'unknown'` —— 它出「尚未确认」，因为这一行是用户决定
   「要不要为它折腾」的关键输入，「尚未确认」本身就有决策价值。

实测证据（真浏览器，149 项断言里的四条）：

```
✓ unknown 渲染成「尚未确认」且绝不含「中国大陆用户不可用」 — 「Perplexity」
✓ chinaUsable=false 照直说「中国大陆用户不可用」 — 「Google AI Pro 学生免费 12 个月」
✓ 详情页出现「适用人群」结构化行 — 「ERNIE-4.5-Turbo-128K 新用户免费额度」→ 开发者
✓ 搜「中国大陆」命中 9 张卡 ≤ 已知可用性 31 条（unknown 6 条不进 haystack）
```

**措辞跨层同源**：RENDER-CORE 在 vm 沙箱里跑、不能 `require`，所以前端必然有一份副本。
副本放在 `index.html` 的 `/* AUDIENCE:START/END */` 块里（**内容由脚本从 `lib/audience.js`
生成**，不是手抄），由 `checkWordingContract()` 做**文本级**逐项比对，`validate --strict`
与 `selftest:audience` 共用。

牙齿实测：把前端 `unknown` 的措辞改成「待确认」→ strict 红并**点名到具体项**：
`AUDIENCE_WORDING.triLabel.unknown：前端「待确认」≠ 后端「尚未确认」`；逐字节复原后回到绿。

## 五、Merge 策略

### 5.1 为什么必须独立于 `score()`

实测复现了一条**会静默毁数据**的路径：

```
采集侧  { source:'智谱AI', type:'deal', discountInfo, expiresAt }  score = 123  → winner
策展侧  { source:'Curated', type:'tool', verified, verifiedAt }     score = 120
结果：人工核过的 availability.chinaUsable=false 被机器推的 true 覆盖，validate 看不出、日志无痕
```

根因：策展条目一旦被推导成 `tool` 就先输 50 分，`SOURCE_PRIORITY` 的 100 分追不回来。
所以 `score()` 继续决定「谁代表这张卡」（旧行为不变），而六个新字段的**取值**由
**逐字段可信度仲裁**独立决定。

### 5.2 仲裁规则

| 情形 | 结果 |
|---|---|
| 一侧缺席 | 取另一侧（并记住它的可信度） |
| 两侧相同 | 保留；贡献者取并集 |
| 一侧 `unknown`、一侧已知 | **已知胜**（信息量优先） |
| 两侧已知且冲突 | **可信度高者胜**；同级时 winner 胜；冲突计入 `stats` |
| 数组（audience / benefitType） | **取并集**，次序 = winner 先（可重跑且稳定） |
| 对象（三态映射） | **逐键**仲裁，不整体替换 |

**可信度归属**：`editorial`（策展来源 + `verified` + `verifiedAt`）> `curated`（策展来源）
> `collected`（其余）> `none`。

**一条记录的整条可信度 = 最终值贡献者里最差的那一档**，记账落在 `provenance.contrib`
并**随记录落盘**。为什么必须落盘：不落盘的话下一次 `loadStore` 读回来的记录没有记忆，
会退回书写期偏高的 `credibility`，假可信度就**按天继承并放大**。

### 5.3 绝不发生的事（都有断言盯着）

- 采集器不得覆盖 curated / editorial 的已知值（**成对断言**：同一对记录只改 `type` 就走两个相反结果）；
- 一次 merge 不得把已知值降级成 `unknown`；
- **provenance 不得为一个它没提供过的值背书**：`fields[field]` 当且仅当该字段
  **全部值的贡献者可信度一致**时保留，否则丢弃该条目（宁可没有出处，也不要错的出处）；
- 冲突必须留痕：`stats.audienceConflicts` + `audienceConflictTitles` + `audienceConflictList`
  （**不能只给计数**）。

### 5.4 本轮在 merge 里抓到的两个真 bug（都值得留档）

| bug | 后果 | 为什么之前的用例全绿 |
|---|---|---|
| `pickMap` 记账漏了**落败一侧** | 真·多来源字段被记成单来源 → `fields` 条目被保留 → 出处署了它没提供过的值 | 只有「逐键冲突」形态能触发 |
| `rebuildProvenance` 的「最低档」**算反了** | 拿到的是**最可信**那一档 → 混源记录仍署 `curated` | **单来源时两者恰好相等**，不可区分 |

第二个尤其值得记：一个方向写反的比较，在单来源输入下与正确实现**不可区分**。
能让它显形的只有「两轮合并 + 逐键冲突」这种组合 —— 由实施者的自测设计抓出来。

## 六、已补齐的数据

### 6.1 数据补齐策略（不是「人工瞎填」）

优先级照要求执行：策展数据全量 → 学生优惠 → 开发者 / API / AI Coding → 高价值额度。
**每一处赋值都必须在 `scripts/tools/audience-backfill.js` 里有对应的一句依据**，
且能在那条记录自己的文本里找到出处。

### 6.2 关键的口径裁决（本阶段最花时间的一处）

「中国大陆可用性」被反复讨论过三轮，最终把边界写死进契约 §2.5.1：

| 证据 | 取值 |
|---|---|
| 官方**明文地区条款** | 按条款取 `true`/`false`（`documented`/`stated`） |
| 官方**明确要求大陆实名认证 / 大陆手机号绑定** | `true`（`inferred` + **note**） |
| 只是国内厂商 / 中文页面 / 面向国内开发者 | **`unknown`** |
| 只是「需完成认证」（没说是哪种） | **`unknown`** |

**为什么第二档可以取 `true`**：大陆实名认证只能由持大陆身份证的用户完成，这条要求本身
就排除了「境外用户才能领」，是所有「没有明文条款」里最强的一类信号；且写成 `inferred` + note
（推理链逐条可核），不是伪装成官方原话。
**为什么第三档不行**：国内厂商证明不了任何一个具体用户能领到 —— 那是把相关性当证据。

我自己第一版在表里写下的 6 条「国内厂商 ⇒ true」被这条裁决删掉了（**同一把尺子量自己**）。

### 6.3 数据收口：把「手工编辑的产物」换成「工具产出的产物」

**发现**：`deals.json` 里 56 条带 `provenance`，credibility 全部是 `collected`；而按 §6.1
的可补依据（策展来源 / 人工核验），这 56 条**一条都不符合**（`migrate --audience` 在同一份
数据上补 0 条）—— 说明这份 provenance 是**手工写进去的**，不是任何工具产出的。

**为什么危险**：`provenance` 按设计**单调退化、永不回写**（§5.3.2 的 `hadProvenance` 短路），
所以下一轮 merge 会把它原样继承下去 —— 一错就是永久的。

**修法**：`scripts/tools/audience-rebuild.js` 重跑一次干净的 merge，而不是字符串级修补：
摘掉策展条目（人工文件是唯一权威）、**剥掉既有 provenance**（否则那条短路会让手工 provenance
永远活着）、重放一轮。收口后：

```
provenance 56 条（全部 collected）→ 32 条（全部 curated）· 指向无值字段 0 处
```

**顺带证实**：`updatedAt` 会说谎 —— 有人原地改了 `deals.json` 却没更新它，于是同一个时间戳
对应两份不同内容（`dist/deals.json` 与源不一致）。这也是「原地手改数据」应当被禁止的理由。

| 4 | `rebuildProvenance` 的最低档取反 | ④「顶层 credibility 下调」红 |

### 8.4 本轮抓到的 8 个真 bug（**都由测试或比对发现，没有一个是自查猜的**）

| # | bug | 后果 | 为什么之前全绿 |
|---|---|---|---|
| 1 | `hasKnown()` 把 `false` 当成「没有数据」 | 一条明确写着「中国大陆不可用」的记录在详情页什么都不显示 | 只测了 `true`/`unknown` |
| 2 | `pickMap` 记账漏掉落败一侧 | 多来源字段被记成单来源 → 出处署了它没提供过的值 | 只有「逐键冲突」形态触发 |
| 3 | `rebuildProvenance` 最低档算反 | 混源记录仍署 `curated`（最可信那档） | **单来源时两者恰好相等**，不可区分 |
| 4 | `contrib` 落成嵌套数组 | `credibilityOf` 静默退回 `collected`、validate 报非法 | 断言只看了「有这个键」 |
| 5 | 贡献者只从当前两侧重算 | 第二轮的 `editorial` 记账消失，混源被重新标成单源 | 单轮测试照不到 |
| 6 | backfill 会删掉 Azure **有原文依据**的 `creditCardRequired: false` | 唯一一条「明说不需要信用卡」的证据被抹掉 | 删减表按字段名一刀切 |
| 7 | backfill 不幂等（决策为空时「跳过写入」） | 上一版被否掉的值永远活着，重跑清理版擦不掉 6/32 条 | 只跑一次不会暴露 |
| 8 | `firstSeen` 被 merge 推晚 | 「首次收录」字段失去意义，且**每轮都重置** | 与 `HEAD` 做全字段比对才看得见 |
| 9 | backfill 重跑会**静默删掉 10 处人工定向补值** | 别人做过的、有原文依据的判断被一把抹平 | 上一个 bug 的修法（"结果由决策唯一决定"）把它引了进来 |

第 3、6、7、8、9 条的共同点：**它们的症状在「只跑一次」或「只看单来源」时不可见**。
这也是本阶段最值得带走的一条经验 —— 断言要挑「能区分两个实现」的输入，而不是顺手能过的输入。

> 第 9 条特别值得记：它是**修 bug 引入的新 bug**。为了让脚本幂等，我改成「决策为空则主动删除
> 该字段」；而我的决策表是**初始**判断，别人后来在文件上做过 12 处定向补值 —— 于是"幂等"
> 变成了"每次重跑都把人做过的判断抹掉"。现在的形状是：重跑会**逐条报出**会被删/改的值并
> **拒绝写盘**（实测拦住 10 处，含 Azure 的 `false`、腾讯/Kimi/魔搭 的 `chinaUsable:true`
> 与 inferred note），要覆盖必须显式 `--force`。

## 十、下一阶段建议

### 10.1 是否适合进入 `v1.2-intent-first-home`

**适合，但建议先做一件小事（半天以内）。** 数据模型已经能表达学生 / 开发者真正关心的问题，
且这件事有了独立的机器守卫；v1.2 需要的地基（枚举稳定、覆盖率可见、详情页可渲染、
门禁能拦住回归）都在。唯一要在动首页之前处理掉的是**上面第 1 条**：
`deals.json` 不可重建意味着任何「首页筛选器读到的数字」都无法追溯它是哪一版数据的产物。

具体建议顺序：

1. **让 `deals.json` 回到可重建**：跑一次真实采集（`node scripts/collect.js --headless`），
   或把手工补充改成采集器的数据源。验收：`audience-rebuild.js --dry-run` 报「已知值被改写 0 处、
   字段被补上 0 处」。
2. **然后才是首页**：audience 筛选器 / 分类入口 / `/student/` `/developer/` `/free-api/`
   —— 它们的成本主要在 sitemap / feed / JSON-LD / 预渲染 / 无 JS 可读这五条既有约定，
   `/status/` 那条路径已经验证过一次，可直接复用。
3. **顺手补两个便宜的缺口**：`deals.json` 与 `dist/deals.json` 的一致性门禁（v1.0 就记着的债）；
   `audience` 参与折叠与排序（本阶段刻意没做，因为会改变折叠卡的标题与落地页）。

### 10.2 本阶段最值得继承的三条做法

1. **「缺席 = unknown，空容器非法」在数据层归一**，渲染层就不必写防御代码 ——
   这一条让「整组不渲染」的实现只花了三行。
2. **措辞必须有单一出处 + 文本级比对**：行为级比对只能覆盖你想到的输入；
   本轮那条「拼句规则」的洞（带地区限制时前后端拼出两句不同的话）就是行为比对照不到的，
   最后靠**模板 + 槽位**才真正只剩一份拼句规则。
3. **多来源字段的出处必须记账到「谁提供了哪个值」**，而不是「谁赢了」——
   「来源不得为它没提供过的值背书」这条红线，只有记账才能落地。
