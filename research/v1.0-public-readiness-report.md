## 二、修复的问题（先复核，再修）

### 1. 有效期状态错误 —— 仍存在，且已发布到线上

**复核**：`ongoing` 只做正向子串匹配。实测 21 条 `ongoing` 里 **11 条**自己的 `validity` 就写着
「官方未标注截止日期 / 以官方…为准」；详情页于是并列两行矛盾文案
（「有效期说明：长期有效（官方模型列表未标注截止日期）」+「活动期限：长期活动（官方有效期说明里
写明长期有效）」）——线上 80 个详情页里 **21 页**带这句伪造溯源。7 条的源头是采集器自己造词
（`cn_docs.js:147` 给「官方只写免费、没写期限」的模型加了「长期有效」前缀）。
`selftest:expiry` 当时 55 项全绿，`:113-118` 是恒真式，`:107` 还**正面断言**
`长期活动（以官方页面展示为准）` → `ongoing`，§8 自己写着「信息性，不作断言」。

**修法（判据 + 出处两层，缺一层页面上仍自相矛盾）**：
- 判据：`ONGOING_POSITIVE_RE`（正向线索必须锚在活动/有效期语义上）**且** `ONGOING_HEDGE_RE`
  无命中（`未标(注)截止 / 以官方…为准 / 以…实时…为准 / 随时调整` 一票否决）；
  前后端同源（`index.html` 的 `ONGOING:START/END` 标记块），删掉第三份更窄且已死的词表。
- 出处：`cn_docs.js`、`headless.js`、`curated_cn.json` 三处改为如实描述「官方未标注截止日期」。
- `index.html` 的 note 去掉循环溯源：「长期活动（官方有效期说明里写明长期有效）」→
  「长期活动（官方写明长期有效）」。
- 「某个权益永久」≠「活动长期」：`额度不过期` / `永久五折` 一律落 `unknown`（按你的要求，
  不假定它等于活动长期）。

**实测影响**：活动期限 `0 / 112 / 21` → **`0 / 123 / 10`**；首页角标 `tg long` 15→**10**、
`tg uns` 35→**40**；含伪造 note 的详情页 21→**0**；卡片 50 / 覆盖条目 80 不变。

### 2. jumpNav 假隐藏 —— 仍存在，且已发布

**复核**：`.jump{display:flex}`（`:303`）与媒体查询里的 `.jump{display:grid}`（`:824`）都是
**作者级**声明，CSS 层叠先比来源再比特异性 ⇒ 作者级无条件盖掉 UA 的 `[hidden]{display:none}`，
`jump.hidden = true` 是**无操作**；全仓 `.jump[hidden]` 规则数为 0（`dist/index.html` 里也是 0）。
验证脚本两处只读 `hidden` 属性（`verify-site.js:1152`、`:1317`）。另发现一个此前完全没被覆盖的
死锚点来源：筛选/搜索把某一档清空后 `#tier-N` 落点消失，而导航仍可见。

**修法**：加 `.jump[hidden]{display:none}`；`render()` 里**逐条**核对落点，只显示有落点的链接、
一条不剩就整块隐藏；断言改量**几何**（`getComputedStyle.display` + `getBoundingClientRect` +
`offsetHeight` + 死链计数），并补齐此前没覆盖的状态（expiry 排序、搜索无结果、清空后恢复）。

### 3. 中文译文不可搜索 —— 仍存在

**复核**：haystack 只有 8 个字段，`deal.zh.*` 一个字都没有，`validity` / `priceLine` 也漏了。
而译文是**渲染出来的正文**（卡片「中文」胶囊 + 详情弹层里的可折叠译文块）。

**修法**：haystack 补 `zhSearchText(deal)`（本条译文 + 折叠卡成员的译文；后者单独存一个
**只用于检索**的串，绝不并进 `deal.zh` —— 那会造出「中文与上方英文对不上」的卡片）、
`validity`、`priceLine`。

### 4. 用户可见文本截断 —— 仍存在

**复核**：`cleanText()` 的注释写着「去截断残尾」，做的事是把上游用来标记「后面还有、只是没给全」
的 `...`/`…` **删掉**；超长时再直接 `slice`，切在半个词中间。实测三类残句：
aitools.fyi **15/15** 条 `description` 断在半句（152–154 字，都没到 200 上限，是省略号被抹掉）、
`c971e33a9cd0` 的 `discountInfo` 恰好 240 字切在 `relocation pla`、
`e237cab7c007` 与另两条是抽句正则跨过「；」「：」抓出的半句。

**修法**：`cleanText` 保留截断语义（上游有省略号就补回 `…`；我们切时先退词边界再补 `…`；
**返回值绝不越上限**；**幂等**）；三处抽句正则的否定字符类补上句读；
存量按「新值去掉记号后必须是旧值前缀」的**机械判据**订正 17 处（未来自于现场抓取复核：
上游 15/15 以 `...` 结尾）。

> 两条**没有**混进去的差异如实记录：Futurepedia 的 Midjourney / Grok 上游真的换过文案
> （「Unlock true digital artistry.」→「Creates images and videos from prompts.」等），
> 不属于本次修复，留给下一次采集（本次真采集已经把它们带进来了，见第五节）。

## 三、CI / 发布链改造

**复核结论（线上实证，不是推断）**：`gate` 与 `deploy` 之间**没有任何依赖**。
同一 SHA `e01dcfc` 上 `gate=failure` 而 `build`/`deploy=success` **照发**；
定时采集那条链路上（机器人 push 不触发任何 workflow）**原本完全没有门禁**；
部署路径上真正跑的只有 `build-local.js` → 它调用的是**非 strict** 的 `validate`。

**改法**：门禁的步骤实现只保留一处 —— `.github/actions/gate/action.yml`（复合 action，13 步）：

```
collect.yml → 采集 → 写盘 → [一致性门禁 + 完整门禁] → git push →(workflow_run)→ deploy.yml
deploy.yml  → prepublish(完整门禁，无 job 级 if) → build → deploy
verify.yml  → gate（PR/push，job 名不变 = 必需检查名不变）→ 复用同一个 action
```

- `verify.yml` 的 job 仍是 `gate`、仍无 job 级 if（被跳过的 job 报 Success = 没跑却算过）。
- `deploy.yml` 新增 `prepublish`：**无 job 级 if**，第一步显式判定「上游采集失败就 `::error` +
  `exit 1`」，然后跑完整门禁；`build.needs: prepublish`、`deploy.needs: build`；
  `build.if` 与 workflow_run 桥接**逐字未动**（断言 (7a)(7b) 仍绿）。门禁红 ⇒ build/deploy
  根本没有机会执行。
- `collect.yml` 的门禁排在 `git push` **之前**（数据有问题就根本不入库），
  逃生口只有一个且必须人工：`workflow_dispatch` 勾 `allow_degraded_run`。

**为什么没按建议抽 reusable workflow `gate.yml`**（三条硬理由，写在 action.yml 头部）：
① 检查名 `gate` 是分支保护的必需名，reusable 调用会把它变成 `<调用方 job> / <被调 job>`
这种形态，只能等第一次 CI 跑完读 check-runs 才知道，且 deploy 再建同名 job 会在同一 SHA 上
出现两个同名检查；② 一致性门禁把「期望项数唯一出处」钉在 `verify.yml` 的一行 `run:` 上，
gate job 变成 `uses:` 调用后就没有 steps，那套机制必须改写；③ 新增 workflow 文件会牵动
`(0b)(3)(3c)(4)(5)` 一串冻结断言。复合 action 三样都避开了（代价：调用方各自保留
checkout / setup-node / runs-on / timeout，各 3 行）。

**一致性门禁同步**（24 → **31 项**，`--expect-checks` 同步更新）：新增 7 条把这个重构本身钉住 ——
`(10)` 复合 action 的**步骤名序列**逐项冻结（谁把真浏览器验收/回归比对/译文门禁从门禁里拿掉就红）、
`(10b)` 每个 run 步骤都给 `shell`、`(10c)` 不含第三方 `uses`、
`(11)` 三个调用方各恰好一次、`(12)` 发布链 needs 关系 + prepublish 无 job 级 if、
`(13)` collect.yml 的门禁排在 `git push` 之前（且提交里必须带上两份跨运行状态）、
`(14)` **未加引号的标量里不得出现「冒号 + 空格」**（见下面的收尾发现）。

**收尾时用真实 YAML 解析器复验，抓到一个会上线的错**：`collect.yml` 的步骤名写成
`- name: CI consistency (bare run: 期望项数…)`——里面的「冒号 + 空格」在块上下文里是**映射分隔符**，
GitHub 的真实 YAML 解析器会**拒绝整个文件**。仓库自带的一致性检查用的是无依赖的缩进读取器，
它把这一行读成合法的 name/值对 ⇒ 本地所有门禁全绿、推上去 workflow 直接 parse 失败、
什么都不跑。用 PyYAML 复验 5 个 YAML 文件时才发现（**这是本轮自己的门禁没有抓到的一类错误**）。
已改成破折号，并把这一类做成断言 `(14)`（扫全部未加引号标量；边界：只查这一种，
不做完整 YAML 校验——那需要引入解析器，与「`npm ci` 之前就能跑」的定位冲突）。
牙齿：把冒号放回去 → `(14)` 红并指出具体位置。

**顺带修好的两个门禁自身的坑**：`run: |` 的 value 是 `null`（判「是不是 run 步骤」只能看键名）；
`parseUses` 把本地 `./…` 引用判成 `malformed`（并在 `(2)` 里会抛 `TypeError`）。

## 四、Source Health（本轮唯一的新能力）

**解决的问题**：首页只写「数据更新 {今天}」，而人工策展条目的 `lastSeen` 每天都在刷新 ——
「某个来源坏了几天」与「某个来源这次没有新内容」在页面上长得一模一样；采集报告只活在当次
运行的内存里，CI 一结束就没了。

- `scripts/lib/health.js` 状态机（规则表写死在文件头）：采集器抛异常 → `failed`；
  无头来源但浏览器没起来 → `failed`（页面根本没渲染，**不许报 healthy**）；
  成功且 0 条 → `degraded`，**连续 3 次才升 `failed`**；成功但掉到上次一半以下 → `degraded`；
  其余 `healthy`。失败时 `lastSuccessAt` **不被刷成今天**。时间一律转北京时间显示。
- 跨运行状态入库为 **`scripts/data/source-health.json`**，与 `deals.json` 同批提交
  （`dist/` 是 gitignore 的，存不了状态）。
- `collect.js` 每轮打印**健康表**（来源/上次/本次/增减/状态/最近成功），并把此前被静默吞掉的
  关键数字**显式打印、0 也打印**：
  `修剪明细: 下架过期 / 超出上限 / 退役垃圾 / 重分类`、
  `来源明细: 采集器失败 n/m · 零产出 n（点名）· 异常 n · 失败 n · 无头浏览器 可用|不可用`、
  `待译 n 条（最老 X 天，宽限 Y 天）` ——`removedExpired` / `removedOverflow` 此前**只被算出来**，
  只有一次性工具 `migrate.js` 打印过。
- `build-local.js`（仍零外部依赖）发布 `source-health.json` 并生成 **`/status/`** 静态页
  （复用首页 style / 主题脚本 / 页脚，**零外部请求**；页脚新增「数据源状态」入口，
  相对路径按深度生成）。页面上只写绝对时间，相对时间由内联小脚本换算 ——
  否则同一份数据在不同时刻构建会产出不同字节，与「连续两次 build 产物一致」冲突。
  自检逐个来源与 JSON 对账（状态标签、条数、状态序列），并断言占位符不残留。

## 七、仍存在的问题

### 需要你在 GitHub 上做一件事：分支保护（无法用代码完成）

**现状（API 实测，非文档转述）**：`GET /branches/master` → `"protected": false`、
`required_status_checks.enforcement_level: "off"`、`contexts: []`；`/rulesets` → `[]`。
也就是说：**现在任何一次直推 master 都不需要过任何检查**。

**推荐做法（Rulesets，只有它能真正满足「不能绕过 gate」）**：

1. 仓库 → **Settings → Rules → Rulesets → New ruleset → New branch ruleset**
2. Name：`master-gate`；Enforcement status：**Active**
3. **Bypass list**：只加 **GitHub Actions**（应用）。
   理由：`collect.yml` 的机器人提交走仓库自带 `GITHUB_TOKEN`，被规则挡住的话定时数据就再也
   进不来；口子用「采集路径自己也跑完整门禁（且排在 `git push` 之前）」补上。
   **不要**加 admin / 维护者角色 —— 那等于人也能绕过。
4. Target branches → **Add target → Include default branch**（即 `master`）
5. 勾选：
   - ✅ **Require a pull request before merging**，Required approvals = **0**（单人项目可自合）
   - ✅ **Require status checks to pass** → Add checks → 搜 `gate` → 选中 **`gate`**
     （这个名字本轮**没有变**，deploy.yml 的新 job 叫 `prepublish`，不会与它重名）
     - ⬜ **Require branches to be up to date before merging** 建议**不勾**：
       机器人每天 2 次推进 master，勾上会让每个 PR 反复「分支过期」
   - ✅ **Block force pushes**；✅ **Restrict deletions**
6. Save
7. 验证两步：① 开一个只改文档的 PR，确认 `gate` 未过时 Merge 被禁用；
   ② 等下一次定时采集，确认机器人的数据提交**仍然成功**（绕过名单生效且没把数据链掐死）
8. **不要**给 `github-pages` 环境加「必需审批人」——那会让每次发布都要人工点一下，
   直接破坏无人值守；Pages 来源保持 `GitHub Actions`。

**保底做法（如果你只想最小改动）**：Settings → Branches → Add branch protection rule →
分支名 `master` → ✅ Require status checks to pass → 选 `gate`。
**但它只拦 PR 合并、不拦直推**，所以达不到你的目标。

## 八、技术债

**本轮新引入 / 新发现的取舍（都写进了 README，不是藏着的）**

1. **发布路径开始依赖 npm registry**：真浏览器验收需要 `playwright-core`，门禁里有 `npm ci`。
   此前「发布前无需 npm install」的说法只对 `build-local.js` 那一步成立。这是「gate 全过才发布」
   的必然代价。
2. **门禁红时定时采集会停更**（浏览器装不上 = 不提交数据）。逃生口只有人工 `workflow_dispatch`
   + `allow_degraded_run`。这是刻意的取舍（数据正确性 > 更新频率）。
3. **回归比对「只能升不能降」**：合法的数据缩减（过期下架、重新折叠）会拦发布，处置方式是
   人工重刷基线（`npm run verify:baseline`，文件在 git 里、留痕可审）。
4. **译文门禁的年龄基准已修正**（收尾时）：现在记的是「进入待译那天」而不是 `firstSeen`，
   代价是多一份入库状态 `scripts/data/zh-pending.json`，且它必须与数据同批提交
   —— 少提交它就会静默退回 `firstSeen`（`(13)` 断言已把「提交里必须带这两份状态」钉住）。
5. **采集整体失败时不落健康状态**：`collect.js` 在「译文不合规 / 零产出」两条硬拦处提前退出，
   那一次的来源结果不会写盘（CI 里那种情况本来也不会提交任何文件）。
   最常见的「单源失败而整体成功」一定会被记下来。
6. **`/status/` 不进 sitemap**（避免牵动 sitemap 的条数断言），靠页脚入口被发现。
7. **`deals.json` 与 `dist/deals.json` 的比对仍然没有门禁**：构建期会重新贴译文，
   所以两者可以有 1 条 `zh` 的差异而无任何检查发现（本轮没做，记在这里）。

**本轮**已知但不修**（下轮或按需）**

- 行视图 `rowHtml` 没有译文入口（译文只在卡片胶囊 + 详情弹层）；
- `writeDetailPages` 只给 `type=deal` 建独立页，38 条带译文的工具条目只能从首页弹层看到；
- `http.js` 的 robots 判定是 fail-open（`Disallow: /` 被跳过、命名 agent 与 Crawl-delay 忽略、
  `followRedirect()` 不做机器人检查）；
- 无障碍基线：全站 0 个 `<h1>`、50 个 `<h3>` 先于唯一的 `<h2>`、无跳转链接、`.tierhead` 是 `<div>`；

  把权重送出去）；结构化数据只覆盖 80 条优惠里的 50 条；
