## 2. 逐条量化

### 2.1 缺口 1：未量测档位（761–1439px）

**扫描口径与读数**（`.arch-v1/static-scan2.cjs`；证据 `viewport-and-sample-coverage.json`）：

门禁真正跑过的宽度是 `1440 / 1600`（全站逐条）、`760 / 360`（**只有 29 页样本集**）、`390`（全站只量 `scrollWidth`）。
产物每个页面的**共享 `<style>`** 里有 **4 条**宽度条件落在这个空档（因为是共享样式，**186 页全部**都活着）：

| 条件 | 与空档的关系 | 规则体（摘要） |
| --- | --- | --- |
| `@media (min-width: 761px) and (max-width: 940px)` | **完全落在** 761–1439 内 | `.topin{gap:12px;height:auto;padding:10px 20px;flex-wrap:wrap}` `.search{max-width:none;order:3;min-width:100%}` `.topstat{order:2}` |
| `@media (min-width: 1100px)` | 下界在空档内（≥1100 在 1440/1600 也生效） | `.plansnav-api{display:inline-block}` |
| `@media (max-width: 900px)` | 与空档相交（760 档**只在 29 页**上跑过） | 窄屏行布局 `.r{grid-template-columns:20px 24px minmax(0,1fr) 64px}` |
| `@media (max-width: 1180px)` | 同上 | `.grid{grid-template-columns:repeat(2,1fr)}` `.need-grid{repeat(3,…)}` |

页面级 `<style>` 里落在空档的条件：**0 条**。

**跑一档 950 会怎样**（`w950`，把第二档换成 950）：`880 项 / 失败 1`，**0 页违规码**；
唯一失败是 **M10 变异牙** —— 它的缺陷藏在 `@media (min-width:1500px)` 里，只在 1600 档咬得到
（读数：`期望 note-narrow · 实测 [narrow-unregistered] · 盒 910px / 有字区域 899px · 视口 950`）。

**「补一档」的成本比看上去大**（`w950add`，真的**加**一档）：**exit 1 + 崩溃**：

```
TypeError: Cannot read properties of undefined (reading 'filter')
  位置：scripts/tools/verify-site.js:7549–7557
  const wideNoteRowsByViewport = { [WIDE_DESKTOP]: wideNoteRows1440, [WIDE_WIDE]: wideNoteRows1600 };
  const wideSummary = {};
  for (const width of WIDE_DESKTOP_VIEWPORTS) { const rows = wideNoteRowsByViewport[width]; … }
```

⇒ 两档写死的读数汇总处必须同步改；M10 的靶位（`@media (min-width:1500px)`）与 1600 档是一体的。
**结论**：价值真实（区间设计上没档位）、假阳性实测 0，但成本 = 一次全页 sweep **＋ 至少一处汇总表 + M10 靶位**的联动改动。

### 2.2 缺口 2：760 档样本集之外

* 基线样本集 **29 页**，其中**只有 13 页**有页面级说明 ⇒ **50 个有说明的页从来没在 760/360 量过**
  （几乎全是 `/models/<slug>/` 详情页；样例：`models/deepseek-v3.2/` · `models/claude-opus-5.5/` · …）。
* 把 760/360 两档扩到**全部 63 页有说明的页**（`notes760`）：**880 项 / 0 失败**，**0 新增码**，
  wall-clock **137.4 s → 170.0 s = +32.6 s**（同机、顺序跑、含变异牙）。
* 极端对照（扩到**全部 186 页**，`all760`）：**880 / 0**，**174.9 s = +37.5 s**。
  ⇒ 从 63 页再扩到 186 页只多 5 s，真正的成本台阶在「29 → 63」（第一次把 models 详情页纳进来）。

**外推依据**：三档样本 sweep 的唯一区别是**导航+度量的页数**（29 / 63 / 186 × 两档），
判据与阈值一字未改；实测增量与页数增量同向且量级一致（+68 次导航 ⇒ +32.6 s；+314 次 ⇒ +37.5 s，
后者更快是因为第三次跑在 OS 文件缓存热的时候）——**我不把这两者当成线性模型**，只把它们当作「同一量级的上界读数」。

### 2.3 缺口 3：② 的轴可被后代 desync（**唯一有实测零码缺陷的一条**）

**产物里今天有没有这种真实形态**：扫描口径 = 全部 186 页内联 `<style>` 里的 `writing-mode` 声明（静态）
＋ 浏览器里逐页 `computed writing-mode ≠ horizontal-tb`（动态）。两条都 **0**：

```
186 页：computed writing-mode ≠ horizontal-tb 的元素共 0 个，分布在 0 页
有说明容器的页：105 页；其中「说明容器自身竖排」的条数：0
```

**人为构造 6 个形态**（`.arch-v1/dom-probe.cjs desync`，在 `archive/` 上用注入改 DOM，不改产物文件）：

| 形态 | ②（列数/列栈） | ①（最窄承载块 content box vs 阈值 1173） | 竖直裁切 |
| --- | --- | --- | --- |
| A 后代横排（auto 宽） | 静默（列 1） | **1104 < 1173 ⇒ 响** | 0 |
| C 后代横排（`width:100%`） | 静默 | 1380 ≥ 1173 ⇒ 不响（**但此形态本身无缺陷**：文本仍满宽横排） | 0 |
| D 后代横排 + 每 16 字换行（t5 的形态） | 静默 | **192 ⇒ 响** | 0 |
| E 固定高 + 裁切 + `nowrap` | 静默 | 1104 ⇒ 响（**余量薄**：只有 6%） | 0 |
| **F 后代横排 + 100% 宽 + 多行 + 外层定高裁切** | 静默 | **1380 ⇒ 不响** | **53px（scrollHeight 143 vs clientHeight 90 ≈37% 行高）** |

**结论**：t5 说「这一形态由 ① 兜住」——对**它构造的那一种**成立（D）；但 **① 并非总兜得住**：
把后代撑满宽（`width:100%`）又多行，① 的判据量就是满宽，② 因为只有 1 列而静默，`note-clipped` 只看横向，
⇒ **零码**，而文本被竖直裁掉三成。这条缺口的**正确修法不是**「把 1 列一律判红」（那会打坏合法的单列竖排），
而是补一条**竖直裁切量**（见 §3 建议 2）。

### 2.4 缺口 4：生效宽 vs 声明值

静态先取产物里所有「声明了 `max-width: N ch`」的规则：**只有 1 条**、只在 **1 页**上：

```
plans/coding/  .pdetailbody { max-width: 72ch; margin-inline: auto; }
```

浏览器里量（先点开详情行，与 §19 的取法一致）：

| 场景 | 生效宽 | 声明的 72ch 现场换算值 | 比值 | 「±20%」判据 |
| --- | ---: | ---: | ---: | --- |
| 基线 | **465.75px** | **465.75px** | **1.000** | 放行（**假阳性 0**） |
| 注入 `width: 300px`（t5 的 R5b，声明文本一字不动） | 300px | 465.75px | **0.644** | **红 ✓（有牙）** |

⇒ 这条判据**今天的假阳性面 = 0**（全站唯一一个受判元素比值恰好 1.000），而它能关掉 t5 攻击榜第 3 名
（成本「一个单位 token」的那条）。加它的顺路收益：§19 现在只按 `entries[0]` 开测（t5 §3.3 的破防），
按 `entries` 逐条做就能一并补上。

### 2.5 缺口 5：竖排 <366 字的假红带

见 §2.3 的两个 0：**产物里没有任何竖排元素**（186 页全扫）⇒ 这条假红带今天**命中 0 页**，
不存在「真实产物被判红」的实例。

**将来出现的可检测信号**（写给下一轮，成本很低）：
① 静态 —— 任一页的内联 `<style>` 里出现 `writing-mode`（我这一版扫描口径）；
② 动态 —— 逐页 `computed writing-mode ≠ horizontal-tb` 的元素数 > 0（本轮的 DOM 普查，186 页约 1 分钟）；
③ 判据侧 —— 一旦出现，**竖排 <366 字**（`0.85 × 列宽 ÷ 单列宽`）会立刻判红：那时要做的**不是加豁免**，
而是在登记清单里为「设计意图的竖排面」（标题条 / 标签）开一条**显式**登记（t5 §4-5 的结论）。

### 2.6 缺口 6：行内 `style=` 与 px 射程

**「已声明」写在哪里**：`scripts/data/narrow-reading-columns.json` 的 `scanScope` 字段，逐字：

> 「产物每个页面内联 `<style>` 里的规则块（与 §22c 的冻结串同一份扫描面）。px / rem 的窄列不在本清单射程内：
> `.detail-main` 的 `width: min(1120px, 100%)` 由 §22b 原有断言（居中 + 宽度 ∈ [1080,1120]）承担，不在这里重复。」

⇒ **px / rem 是逐字声明出射程的**（并且指明了另一条判据接手）；
**行内 `style=` 没有被单独点名**，但扫描面写成「产物每个页面内联 `<style>` 里的规则块」
—— 按字面，行内样式属性在射程外，属**隐含**声明（t5 的措辞「已声明」对这一半是**近似成立**）。

**若把行内 `style=` 纳入射程**（我扫了全部产物）：

| 量 | 值 |
| --- | --- |
| 带行内样式的页面 | **6 页** |
| 行内样式属性 | **61 个**（布局类 **52** 个，全部在 `index.html`：`width:24px`/`48px` 这类 SVG 尺寸） |
| 其中含 `ch` 的 | **0 个** |

⇒ 成本 = 一个小 `style="…"` 解析器（分号切分）+ 把它加进扫描面；**假阳性 ≈ 0**（今天一个 ch 都没有）。
但**只有 1 个已知绕过形态**（t5 的 R10）、产物里 **0 处**，所以适合**折进「谁动扫描面谁顺手做」**，不值得单独排一轮。

**px 射程**：**不建议**纳入。产物里 `max-width: <n>px` 全是合法布局手段
（`.detail-main` 1120px、`.dpane-src` 820px、卡片图标 24px…），要判「这个 px 宽度是不是窄阅读列」
得先有「什么算阅读列」的语义判据 —— 那不是补一条断言，是开一个新判据面（假阳性风险高、收益低）。
**正确的替代**是 §3 的建议 1：在 **ch 口径**上加「生效宽 ≈ 声明值」，把「声明文本没变、生效宽被换掉」这条堵住。

## 3. 裁定：按「价值 / 成本 / 假阳性风险」排序

> 每条写清：**补哪条判据 · 加在哪 · 需要什么样本或夹具 · 不许放宽什么**。

### 建议 1（首选）· 生效宽 ≈ 声明 ch ±20%
* **补什么**：`§19` 在量完居中之后，再断言 `|生效宽 ÷ (N × ch 现场换算值) − 1| ≤ 0.2`（N 取自登记条目的声明文本）。
* **加在哪**：`verify-site.js` §19（登记清单 `scripts/data/narrow-reading-columns.json` 是声明侧的唯一出处）。
  顺路把 §19 从 `entries[0]` 改成**逐条 entries**（每个条目用自己声明的选择器与 ch 值）。
* **样本/夹具**：不需要新样本 —— 就是现有那 1 条登记（`plans/coding/` 的 `.pdetailbody`），
  夹具用 t5 的 R5b（`width: 300px`）——本轮已实测该形态比值 0.644。
* **不许放宽**：容差不要超过 ±20%（0.644 与 1.000 之间余量充足）；**两侧都要判**（`min-width: 1400px` 那类高估一侧同样要红）；
  不要顺手把 px/rem 的宽度拉进来（`.detail-main` 有 §22b 自己的口径）。

### 建议 2 · 竖直裁切量（② 的竖排对应物）
* **补什么**：给 `<main>` 内每条说明加一条读数 `scrollHeight > clientHeight + WIDE_TOL` ⇒ 新码或并入 `note-clipped`
  （并入更省：它本来就是「自身裁切」这一族）。
* **加在哪**：`verify-site.js` §22c（`wideMeasure` 里多量一个 `scrollHeight/clientHeight`，`wideProblems` 里多一条判定）。
* **样本/夹具**：本轮的形态 F（后代撑满宽 + 多行 + 外层 `height:5.6rem; overflow:hidden`）——实测 53px/37% 被裁、零码；
  t5 的 V3（竖排 `nowrap + overflow:hidden`）同类。
* **不许放宽**：**必须加前置条件** —— 只在「盒子真的会裁」时判（`overflow` ∈ {hidden, clip, auto, scroll} 或 `height` 不是 auto）；
  `overflow: visible` 的说明内容溢出时 `scrollHeight > clientHeight` 是正常的，直接判会制造假红。
  也不要拿它替代 ②（`columnSpan`）或把「1 列 + 无裁切」的正常竖排判红。

### 建议 3 · 760/360 档扩到 63 页有说明的页
* **补什么**：把样本集从「29 页现场推导样本」扩到「全部有页面级说明的页」（63 页）；其余判据一字不动。
* **加在哪**：`verify-site.js` 的 `wideSampleSet()` 调用点（样本集来源），或把「有说明」作为样本集的第一类成员。
* **样本/夹具**：不需要新夹具 —— 63 页本身就是样本（几乎全是 `/models/<slug>/`）。
* **不许放宽**：不要为了省时间把样本集**改小**；不要动 760 档的物理前置条件（现场列宽 > 70ch 才判 ②）。
* **成本读数**：+32.6 s（29→63 页 × 两档），新增码 **0**。

### 建议 4 · 补一档 950（或把 761–1439 补满）
* **补什么**：`WIDE_DESKTOP_VIEWPORTS` 加一档（950 或 1024），并同步三处联动：
  ① `wideNoteRowsByViewport` 的建表（现在只建 1440/1600 两个键）② 依赖两档的 metrics 汇总
  ③ M10 变异牙的靶位（现在锚在 `@media (min-width:1500px)`）。
