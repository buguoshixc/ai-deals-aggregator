# 采集链路加固：外部安装步骤必须有界（`collect-robustness-v1`）

> 分支 `collect-robustness-v1` · 基线 `origin/master = 11f9ee0`（`secondary-page-intro-changes-v1` 合并后的 tip）
> · 2026-10-08 · 取证见 [`research/_raw/collect-robustness-v1/incident.json`](_raw/collect-robustness-v1/incident.json)
>
> **一句话**：定时采集卡在浏览器内核下载上，`continue-on-error` 对「卡住」无效 ⇒ 30 分钟 job 预算被吃光
> ⇒ 整轮取消、静态采集一步没跑、数据停 24 小时。本轮给那一步加上**小于 job 预算的上界**，
> 并补一条会红的断言 `check:ci` (20) 把「无人值守链路里的外部安装步骤必须有界」钉住。

---

## 1. 事故（实测事实，不是推断）

| 项 | 读数 |
|---|---|
| 出事的那一轮 | `Collect AI Deals` run **37667276213**，2026-10-07T18:29:51Z 触发，**cancelled**，墙钟 **31.3 分钟**（job 上界 **30**） |
| 卡在哪一步 | 第 7 步 `Install browser for JS-rendered sources` —— `npx playwright install --with-deps chromium` |
| 后果（步骤级） | 第 8–11 步（`Run collectors` / `Validate new data (strict)` / `CI consistency` / `Gate`）与第 15 步（`Commit and push if changed`）**全部 skipped** —— **静态采集一步都没跑** |
| 后果（数据级） | `deals.json` 的 `updatedAt` 停在 **2026-10-07T12:29:57+08:00**；取证时已陈旧 **24.2 小时** |
| 后果（发布级） | 紧随其后的 `Deploy to GitHub Pages`（run 37671289227）在 11 秒内失败于 `Refuse to publish when the upstream run failed` —— **按设计**拒绝发布（上游被取消 ⇒ 不发布未过门禁的数据），不是缺陷 |
| 正常轮有多快 | 最近 20 轮里 **15 轮成功**，整轮 **3.0–6.5 分钟**（含这一步） ⇒ 30 分钟预算平时用掉不到四分之一 |

### 1.1 为什么这不是「偶发网络抖动，无需处理」

那一步的注释里写着的意图是：

> `continue-on-error`：装不上也不能拖垮整条已经稳定运行的静态采集链路 ——
> 那种情况下无头来源会各自报错并产出 0 条（健康表判成 `headless_unavailable` 而不是 `healthy`）。

**这条承诺对「失败」成立，对「卡住」不成立。** `continue-on-error` 只在步骤**结束**（失败）时生效；
一个挂在网络上下载的步骤根本不会结束，于是唯一的上界是 job 级的 30 分钟 —— 而那意味着**整轮陪葬**。
事故当时的形状正是如此：想保住的「静态采集」恰恰是被牺牲掉的那一部分。

### 1.2 另一件如实记录的事：那一轮迟到，而不是缺席

事故之后的那次 cron（`0 0 * * *` = 北京 08:00）**没有缺席** —— 它在 **04:39Z（北京 12:39，晚 4.65 小时）**
才起来（GitHub 对定时任务在负载高时会推迟），取证时它正在正常跑：第 7 步这次**成功**、
第 8/9/10 步全成功。也就是说：

* 调度推迟是 GitHub 侧行为，**仓库里没有可修的东西**（但「推迟」与「卡死」叠加，就是这次 24 小时停更的实际形状）；
* 数据随后由系统自己补上了 —— 本轮**不需要**（也没有）手工重跑采集，更没有造任何数据。

## 2. 改了什么（产品侧 2 个文件 + 1 条规则）

| 文件 | 改动 |
|---|---|
| `.github/workflows/collect.yml` | 给 `Install browser for JS-rendered sources` 加 **`timeout-minutes: 8`**，并把上面 1.1 那一段理由、事故 run 号与「8 分钟的取值依据」写进注释（注释是给下一个人的，不是给 CI 的） |
| `scripts/tools/check-ci-consistency.js` | 新增断言 **(20)**：该步骤必须同时满足 ①`continue-on-error: true`、②`timeout-minutes ∈ [1,10]`、③**小于 job 级 `timeout-minutes`**；读不到 job 预算时**判红**（fail-closed，不静默跳过）。名字同步进 `FROZEN_ASSERTION_NAMES`（看门狗会比对名单等值） |
| `.github/workflows/verify.yml` | `--expect-checks=38` → **39**（项数的唯一出处就是这一行；collect/deploy 的裸跑都从它派生） |
| `docs/DESIGN-RULES.md` §9 | 新增长期规则 **N5**：无人值守链路里的外部安装 / 下载步骤必须有界，且上界必须小于 job 预算 |

### 2.1 取值为什么是 8 分钟

* 历史成功轮**整轮** 3.0–6.5 分钟（含这一步）⇒ 一次正常安装远小于 8 分钟，不会误伤；
* 8 < 30（job 预算）⇒ 卡住时先杀掉这一步，`continue-on-error` 生效，采集与门禁照跑；
* 上界写成 1–10 的区间：大于 10 就失去「有界」的意义（历史整轮才 6.5 分钟），小于 1 是打字错误。

## 3. 牙：两条负例实测（都当场变红，再逐字还原）

| 变异 | `npm run check:ci` 的读数 |
|---|---|
| 删掉 `timeout-minutes: 8` | **✗ (20)** `该步骤没有 timeout-minutes —— 卡住会吃光 job 预算、整轮被取消（2026-10-07 实测，数据停 24 小时）` · 39 项 / 失败 1 / exit 1 |
| 把上界写成 `30`（= job 上界） | **✗ (20)** `timeout-minutes: 30 不在 1–10 的合理区间…；步骤上界 30 ≥ job 上界 30 —— 卡住时仍然是整个 job 被杀，上界形同虚设` · 39 项 / 失败 1 / exit 1 |
| 还原成 `8` | **✓ (20)** `内核安装步骤：continue-on-error + timeout-minutes 8 < job 预算 30` · **39 项 / 失败 0** |

顺带证明「项数钉在调用方」这条纪律仍然成立：`verify.yml` 改成 39 之后，**不带参数**裸跑
（collect.yml / deploy.yml 的调用方式）也从那一行读到 39，两端一致。

## 4. 这一轮**不做**的事（如实划界）

| 不做 | 为什么 |
|---|---|
| 改采集器 / 改数据 / 改门禁判据 | 事故与采集逻辑无关：卡点在「下载浏览器内核」，采集器一次都没被调用 |
| 给这一步加自动重试 | 该步骤已被 `continue-on-error` 兜住（装不上 ⇒ 两个无头来源降级为 `headless_unavailable`，健康表与 Summary 里都看得见）。重试只会把「卡住」的时间再乘一遍 |
| 加「数据陈旧」告警 | 站点上「数据更新时间」是用户可见的既有信号；把告警塞进 PR 门禁会在正常的长间隔 PR 上误报（一条在正常状态下失败的守卫比没有守卫更糟）。要做也应该是独立的运维动作，不在本轮射程内 |
| 触发手工采集补数据 | 那一次 cron 只是**迟到**——它在 04:39Z 自己跑起来了并且成功。**不造数据、不重跑**（`workflow_dispatch` 的逃生口留给真正需要的时候） |
| 调整 job 级 30 分钟预算 | 成功轮只用 3.0–6.5 分钟，预算是宽裕的；问题从来不是「预算太小」，而是「这一步没有自己的上界」 |

## 5. 残余风险（P2）

| # | 风险 | 处置 |
|---|---|---|
| 1 | GitHub 定时任务**推迟**（本轮实测晚 4.65 小时）在仓库里无法修 | 如实记录（`incident.json` 的 `scheduleDelay`）。有界化之后，「推迟」不再叠加「卡死」⇒ 最坏情况是这一次采集晚几个小时，而不是数据停一天 |
| 2 | 上界本身是「猜的」：8 分钟对当前 runner 足够，若将来内核体积显著变大可能误杀 | 误杀的代价是**两个无头来源降级**（不是整轮失败），且 `Failed sources` 与健康表会写明原因；注释里已写清取值依据，改这个数字时 `check:ci` (20) 会要求它仍落在 1–10 且小于 job 预算 |
