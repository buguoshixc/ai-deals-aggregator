# 视觉复核（原计划 B4）—— 独立视觉评述

> **这份文件补上的是哪一块**：`README.md` §3/§6 曾记「视觉评述未完成」——原计划把参考站截图交给视觉模型
> 独立复核，但该模型所在 provider 返回 HTTP 402，5 个审阅任务全部失败。**2026-09-23 已跑通并补齐**。

## 1. 怎么跑的

- **模型**：`deepseek-v4-flash-vision-exp`，provider **`deepseek-official`**
  （该模型在 profile 里声明 `inputModalities: [text, image]`，`imagePixelBudget: 640000`、`imageMaxBytes: 1048576`）。
- **对象**：20 个参考站（12 同类 + 8 标杆）+ 我们自己的 3 个产物快照（`ours-A-light` / `ours-A-dark` / `ours-rows`）。
  分 6 批并发，每批 3–4 个对象，各自独立作答。
- **要求**（写进 prompt 的硬约束）：① 只写图里真的看到的，不推断代码、不编造数字；
  ② 某张图读不出来就如实写「未读到图」，**不许用常识补齐**；③ 每站回答四个字段：
  `hierarchy`（层级靠什么建立）/ `density`（密度与条目形态）/ `legibility`（可读性直观印象）/
  `notable`（**DOM 度量看不见、但肉眼能看见**的一点）。
- **产出**：23 条评述，全部 `sawImage = true`（没有一条是编的）。以下逐条照录，**不替读者解释**。

### 为什么前几次没跑成（诊断结论，供以后参考）

| 尝试 | 结果 | 原因 |
|---|---|---|
| 2026-09-22 首次 | 5 个任务全失败 | provider 返回 HTTP 402（余额不足）—— 当时的记录是准确的 |
| 2026-09-23 充值后重试 | 探针仍返回空 | **我用错了 provider id**：试了 `deepseek`、`llm-deepseek`，都不存在 |
| 用正确 id 重试 | ✅ 6/6 成功 | 组合后的 profile 里默认 agent 模型写的是 **`provider: deepseek-official`**（见 `dsh --profile web --dump-config`） |

账号本身一直是好的：用凭据库里的 key 直连 `api.deepseek.com`，`GET /v1/models` → **200**，
且 `deepseek-flash` 声明 `input_modalities: ["text","image"]`；`POST /v1/chat/completions` → **200**、正常计费。
**结论：这条链路上唯一的问题是「provider id 猜错」，不是余额。**

## 2. 已知限制（先说清楚，免得被下面的结论误导）

1. **读图有边长上限**：`research/_raw` 下 108 张 PNG 里有 **11 张超过模型的 8192px 单边上限**
   （最大 `free-for-dev/shots/desktop-full.png` 14940328 字节）。
   超限时审阅者被要求改读 `mobile-first.png`，于是这些站的结论**只覆盖手机首屏**，或在降采样图上得出。
   逐站受影响情况已写在各自的 `notable` 里（如 ai-bot.cn、artificialanalysis.ai、framer.com、futurepedia.io、
   linear.app、openrouter.ai、raycast.com、stripe.com、superhuman.com 都注明了这一点）。
2. **`free-for-dev` 只读到 5 段切片中的第 1 段与第 5 段**，中间未读 —— 它的结论仅覆盖页首页尾。
3. **发现截图本身可能是拼接产物**：`openrouter.ai` 的整页截图里，同一屏 Models 列表在约 16400 / 32800 / 98400 px
   处**原样重复**，重复段之间是整片纯白。也就是说**「整页截图的高度」不等于「真实内容长度」**——
   凡是以整页截图高度为口径的量，遇到这种站都会被高估。这条与 §4 的横向观察同样重要。
4. 降采样过的图上**字号无法细究**，这类站的可读性结论只能算方向性判断。

## 3. 参考站（20 个）

### 同类垂直站（12）

**ai-bot.cn**（仅读到手机首屏）
- hierarchy：靠色块加字号——首屏正中超大渐变色品牌字「AI工具集」（上方叠一枚 AI-BOT.CN 胶囊徽标）独占焦点，下面用粉/蓝/绿/浅蓝四块马卡龙色瓷砖配粗黑字做入口分层，几乎不靠字重梯度。
- density：密：一块手机首屏里塞了品牌区、五个导航标签、一条通栏宽搜索框、五个搜索源、四宫格入口、两条全宽广告条以及「热门工具」标题和两张工具卡；形态是「色块瓷砖＋两列小卡」，不是表格也不是单纯紧凑行。
- legibility：工具卡描述与搜索框占位文字都是浅灰，在白底上偏淡；两条广告条里的小字说明已经糊到读不出；其余粗黑字与深蓝标题对比正常。
- notable：两条全宽横幅广告硬插在内容流中间，把「四宫格入口」和「热门工具」隔成两段，形成与页面浅灰底无关的彩色条带；右下角浮着一个圆形按钮，正压在工具卡的描述上；入口瓷片用的是卡通插画而非图标，图片占比明显高于卡片其它元素；搜索框为浅灰填充，与浅灰页面背景几乎融为一片。

**aitools.fyi**
- hierarchy：主要靠图片——每张卡顶部大比例的工具截图承担最大视觉重量，紫色只作标题、按钮与分类胶囊的点缀色，层级另由字号加灰度差补足。
- density：桌面为密：三列网格一屏可见约十张卡，每卡一图＋两行灰色描述＋两枚描边标签；形态是「上图下文」的竖向卡片。手机端相反，一张卡几乎占满一屏，描述字号明显放大，节奏很疏。
- legibility：卡片描述与页脚链接是中性灰、字号偏小，可读但偏淡；紫色标题与紫底按钮对比足；卡片内截图缩略图里的文字不可读。
- notable：第一排三张卡的缩略图高度不一致——最左一张明显更高，另两张图片顶边下移，整排图片顶边参差；右侧网格外浮出一枚紫色标签压住列宽；页脚是整块深藏青，与上方大面积纯白形成硬切；卡片普遍用极细浅灰描边＋大圆角。

**appsumo.com**
- hierarchy：靠尺度加纯色块——正中巨大的黑色标题配整宽明黄按钮形成最强层级，其次是白卡浮在浅灰底上的面块对比；字号梯度不大。
- density：桌面首屏被促销弹窗占掉大半，实际可见的主体只是背后三列紧凑条目，偏「紧凑行」；手机首屏很疏：一张带浅紫渐变边的白色圆角卡占据大半屏。
- legibility：弹窗内灰色正文、「No thanks」以及最底部的极小免责声明明显偏小偏淡；黑色粗标题清晰，黄色按钮上的黑字很扎实。
- notable：首屏真正的视觉重心是一个促销弹窗，页面主体被它遮住；被遮住的背景四周散布彩色 App 方牌作装饰。手机端手机首屏底部露出的是一枚巨大黑色数字字形（「1」与相邻灰色「11」形状）——纯装饰性的大号序号，是度量层面看不到的元素。

**artificialanalysis.ai**（仅读到手机首屏）
- hierarchy：靠衬线大标题加留白——黑色高对比衬线体「Independent analysis of AI」与四周大片白底构成唯一焦点，紫色只出现在 Premium 按钮、标题前的小色块和图表柱上作强调。
- density：疏：首屏只有大标题、一行副标题、「Highlights」分节标题和一张图表卡，一个卡片独占一屏，完全没有列表或表格的密集行。
- legibility：正文纯黑大字很清楚；偏弱的是卡内灰色图注、斜排的小字模型名，以及柱内白色数字——白字落在浅棕与浅蓝柱上时对比偏低；底部浮出的中文提示条直接压住了下一张卡的图注。
- notable：图表卡里柱子等宽、柱间留白很大，x 轴标签斜排并悬在卡片下缘之外，形成「图表即主视觉」的版式；卡片以下是接近整屏的空白，视觉重心偏低且居中。

**devtk.ai**
- hierarchy：靠字号断崖（巨型粗黑标题 vs 明显更小的副文/卡片正文）加左侧一条蓝色强调色与白色留白卡片建立层级。
- density：中。首屏是左对齐大标题加两枚左对齐按钮，下方三张横向并排的白色描边统计卡，再往下是三栏工作流卡与九宫格核心工具卡；卡内是大数字加小标签的疏松排布。
- legibility：好。正文与卡片描述是较浅的灰蓝字，但字号够大，在桌面与手机上都能轻松读。
- notable：Hero 与移动端首屏顶部有一条淡紫到白的柔和渐变带，占了不小面积却几乎不承载信息；移动端统计卡被拉得极高极疏，一屏只装得下一张半。

**free-for-dev**（只读到 5 段切片中的第 1、5 段）
- hierarchy：靠纯文字本身建立层级——粗体黑字的大标题与章节标题、加粗的条目名、以及整段整段的正文，外加唯一的绿色链接色；最主要手段是字重与缩进。
- density：桌面极密。左侧是窄目录栏，右侧是一列几乎无分隔、无卡片的连续绿色链接与项目符号条目，属文档式长列表。手机首屏是一整屏纯正文段落，没有一点卡片或按钮。
- legibility：正文是偏灰的深灰色、字号偏小、行距偏紧，长段落连排时明显发灰；条目名与链接的绿色也偏淡。属于可读但吃力的文档型排版。
- notable：整页几乎没有任何视觉装饰：无卡片、无边框、无按钮、无阴影，唯一的一处图像感是右上角一片绿色三角色块；桌面端目录栏的空白与右栏的密排形成强烈不均。手机首屏完全没有导航栏、没有 CTA、没有图，与桌面端双栏结构差别极大。

**futurepedia.io**（读的是降采样版）
- hierarchy：靠大面积的饱和蓝色渐变面板充当容器、白字压在其上建立层级，配合段落交替的蓝底块与白底卡片。
- density：密。首屏被巨型白色标题、浅蓝副文、两枚白底胶囊按钮、TRUSTED BY logo 墙占满；往下是蓝色分段式标签栏加一列带图标、名称、右侧收藏数与上升数的工具卡。手机端工具卡是大图标加名称加右侧数字的紧凑水平行。
- legibility：可读性尚可但对比被削弱：hero 副文与 logo 墙是浅色半透明压在蓝底上，偏淡；下半部分文字在降采样后已难以逐字辨认。
- notable：装饰性色彩体量极大：顶部一整块蓝色渐变面板，中段两组各四张紫粉渐变缩略图几乎只起色彩填充作用，形成整齐的棋盘状色块节奏；TRUSTED BY 的 logo 被调成低透明度灰白，是当纹理用而非当信息用。

**futuretools.io**
- hierarchy：主要靠"极端字号+字重反差"：近黑底上几处巨大白色标题压过一切，全页唯一的高饱和紫色只点给主按钮和标题里的 ONE。
- density：首屏偏疏，往下立刻转密：左侧 AI News 是十几条紧凑行，右侧 TOP TOOLS 是一栏近二十行的"小圆标＋名称＋计数"行。手机首屏的副段落是中灰压黑，仍可读。
- legibility：主标题白字压近黑底、对比很强；真正偏弱的是次级信息——新闻行下方的来源/日期小字、工具行右侧的计数、页脚四栏链接，都又小又灰。
- notable：桌面整幅的视觉重心被顶部一张订阅浮层抢走了，背后的 Stay ahead in AI 大字被压暗模糊；而同一页的手机首屏完全没有这层遮挡——两端给人的第一印象不是一个站。另外手机首屏底部还收在一片扩散的紫蓝光晕上，纯装饰、不承载任何内容。

**llm-prices.com**
- hierarchy：层级只靠字体大小/粗细＋"浅灰页底上浮一块白卡"的明度差来建立；全页没有图片、插画、头像或色块，唯一的色彩是表格里几条浅蓝高亮行。
- density：密：整页基本就是一张表——四列、几十行由细线分隔的紧凑行，从首屏一直拉到底；手机端反过来，首屏只有两张白卡、全是表单字段，很疏。
- legibility：表内型号与数字深色压白底，对比没问题，但字号偏小、行距紧；真正发灰的是斜体注释与左栏说明文字。另一处观感问题不是"灰"而是"空"：左栏表单下方留着一大片与整张表等高的空白色带。
- notable：最抢眼的是比例失衡：左边一条窄表单栏、右边一张延伸到底的巨大表格卡，左栏在表单结束后留出一条与整张表几乎等高的空白色带；表格中那几条浅蓝高亮行沿页面向下形成规则的色彩节拍，是全页唯一的视觉韵律。**纯文档气质、零图像，这是眼睛一看就知道、但 DOM 度量不会报警的东西。**

**openrouter.ai**（整页图超限；且发现拼接重复）
- hierarchy：层级几乎全靠排版建立：加粗黑体的大字压过灰色的正文与小号元信息，再用极浅的横向分隔线切分条目；品牌紫只出现在左上角 logo 和右上角实心 Sign Up 按钮上。
- density：密——首屏就是信息密集的目录页：左侧一整列筛选条件，右侧每行一个模型（图标＋名称＋两行描述＋context、价格等元信息），属紧凑列表/表格形态；手机改成大卡片，密度明显下降。
- legibility：模型名黑色加粗、清晰；描述正文明显偏小而且是浅灰，元信息更小更浅，属发灰的低对比次要文字，长列表连读会累。
- notable：**这张长图是拼接产物**——同一屏 Models 列表在约 16400、32800、98400 处原样重复，重复段之间是整片纯白（两个不同位置的切片逐字节相同）。也就是说视觉上"整页高度"远大于真实内容长度，**纯 DOM 量出的页面高度会把内容量估得极大**。另外桌面与手机首屏都是同一个 Models 目录页，没有营销式大图 hero。

**theresanaiforthat.com**
- hierarchy：靠「字号落差」建立：一条巨大的白色超窄体全大写标题占掉最上方最重的视觉块，其余全部压成小字，绿色只留给注册类按钮，红色留给顶部横幅条。

- legibility：有明显发灰的次要文字：深海军蓝底上的灰色描述行、时间戳、行尾小标签对比度偏低；手机图里描述被窄屏截断成省略号，小徽章/标签片字号很小。
- notable：手机首屏有一条半透明的深色浮动底部标签栏直接压在信息流最后一行上，把该行下半截遮住；广告行只在左侧时间戳栏里用极小的「Ad」并附曝光数字与自然行混排，肉眼几乎与时间戳同色。赞助卡用「描边卡片 + Sponsor 小片骑在顶边框线上」的装饰手法。

**toolify.ai**
- hierarchy：首屏靠「渐变大标题 + 紫色实心按钮」建立；一旦滚过 hero，层级迅速扁平化——中段三栏字号几乎同级，末段 Featured 网格更是一整片同尺寸小瓷砖，只能靠缩略图颜色区分。

- notable：肉眼最突出的是「装饰先于内容」：顶部大片柔和渐变铺满整个 hero，衬得下面成百上千块同规格小瓷砖形成一堵均质的「砖墙」，几乎无法用视觉快速分区。**桌面端左栏的小推广位与中间正式列表长得非常像，肉眼很难一眼分辨付费位**；页面中段一列带照片的新闻条，是全页极少数出现真实图片的地方。

### 设计标杆（8）

**framer.com**（读的是等比缩小副本）
- hierarchy：靠巨大的纯白粗体标题压在近全黑背景上建立层级，配合白底黑字与描边两枚按钮的实/虚对比。
- density：中。桌面首屏是一行大标题加两枚按钮，随后是深色产品界面截图集群，段与段之间留大片黑。移动端首屏只有导航、超大标题、两枚按钮、一行 New: Skills，以及一块被裁切的大视频面板与 logo 墙。
- legibility：正文级文字在深色底上偏灰偏暗、字号偏小，密集的深色卡片里的小字尤其不醒目；但作为导航与区块标签用途仍然可辨。
- notable：整页几乎全黑，唯一的高亮资源押在一块发光的深蓝渐变视频面板上——视觉重心被这一块发光矩形独占；生态 logo 墙是低透明度灰字贴在黑底上，Framer 把它当纹理而非信息；**图像面积远大于文字面积**。

**linear.app**（读的是等比缩到一半的图）
- hierarchy：几乎不用边框和色块，层级完全由字号/字重＋大面积的纯黑留白分层：标题纯白、正文压成暗灰、说明更小更暗。
- density：疏：每个区块基本是"一个大标题＋一段说明＋一张大截图"，黑底留白极多；全页没有表格、没有密集列表。
- legibility：大标题清晰；但大量次要文字是暗灰压在纯黑上，明显低对比且偏小，远看几乎糊成一片。手机截图除顶栏外全黑，无从判断。
- notable：肉眼能看到两件度量说不清的事：一是**桌面整幅最上方是一大片纯黑空场、没有任何标题文字，全页最大的一段留白在"页首"而不是内容之间**；二是在近乎单色的黑里，末尾并列的两张引言大色块（一张近白、一张高饱和黄）是全页唯一的大面积彩色，视觉重量在长滚动末端突然跳起。手机端更极端：只有顶栏渲染出来，首屏其余部分全黑无内容。

**notion.com**
- hierarchy：靠"白底＋超大黑色居中大标题"的字号反差定调，标题里嵌一枚薄荷绿药丸是全页唯一彩色；往下用大量圆角白卡＋细灰边＋大截图分节。
- density：中：hero 很疏，中段骤然变密——logo 墙、三张功能卡、五个彩点快捷卡紧挨在一起；条目形态是大圆角卡片，不是紧凑行也不是表格。
- legibility：标题与正文对比很好；偏弱的是那些极小号的说明行、卡片内的小标签和页脚四栏链接。最难读的一处是引言卡：小号深色引文直接压在红/蓝/黄三块高饱和渐变上。
- notable：hero 大截图右上角有一处手绘圈注＋小箭头，左侧白边上还站着一个很小的黑色手绘小人，让整块 hero 带"草图感"；**三张功能卡里第一张装满了界面内容，第二、三张面板基本是空白白块，整排视觉重量明显偏左——这类"某张卡其实是空的"只有看图才发现**。页顶还有一条中文语言提示条压在导航之上，把整个 hero 往下推。

**raycast.com**（读的是降采样切片）
- hierarchy：靠"黑底＋大面积留白＋白色粗体大标题"分层：每组内容由一句居中大标题领起、下面跟产品截图或卡片；首屏的红色斜向光束图是全页唯一的高饱和视觉锚点。
- density：疏——首屏只有一句标语、一个下载按钮和一个小小的胶囊链接；往下是大尺寸产品截图、横向扩展卡片、3 栏小卡与 5 列页脚链接。
- legibility：白色大标题很清晰，但大量说明文字与图注是灰色压在黑底上、偏暗；深色产品截图叠在黑背景里边界几乎消失。
- notable：1440 宽里内容只占中间一条较窄的栏，两侧留出很宽的黑边，形成很强的竖直"隧道"式重心；首屏红色光束图几乎铺满整屏，占比远超文字；页脚之前还有 3D 设备渲染图和整块键盘键位图这类纯装饰图片，占了很长版面却不承载文字信息。

**stripe.com**（读的是降采样切片）
- hierarchy：靠巨大的彩色斜向渐变色块与超大的中文标题对撞来建立层级，并用一条深藏青反白数据带做节奏断点；普通正文与卡片说明被压得很小很淡，退到背景里。
- density：中——首屏是标题＋两个按钮＋一行客户 logo；之后是大白卡与纯文字卡交替，中段一条深蓝数据带，属大卡形态。
- legibility：深蓝带上的反白文字清楚；但浅色区块上的正文与卡片说明偏小、灰度偏浅，首屏左上角那行统计小字字号极小，是典型的发灰次要文字。
- notable：**页面里散布着好几块面积很大的纯白/极浅灰空白矩形（多出现在产品展示区，像是媒体没渲染出来的占位），它们撑起版面高度却没有可见内容——只量 DOM 盒子会把这些算成内容面积。** 另外首屏渐变彩带越过导航区域、标题压在彩带之上形成叠层。

**superhuman.com**（桌面被自动降采样到约 905px 宽）
- hierarchy：靠大面积的深紫/深蓝底色分块＋高对比标题来分层：每条产品线换一次底色，块内再用浅色卡片与深色卡片对撞。
- density：中——桌面首屏只有一句标题＋两个 CTA，往下是 3 张白色并列小卡、2×2 大卡网格、一条淡紫证言带；卡片面积大、文字少。
- legibility：深色块上的正文多为中灰/淡紫小字，看上去发灰、对比不足；深色区里的截图被缩得很小，细节不可辨。
- notable：手机首屏 CTA 下方留出将近半屏的空白深紫区域（像是没渲染出来的背景图/视频），整屏重心被压到底部那条横条上；桌面页脚底部还有一个几乎与底色同色、占满整幅宽度的巨大"SUPERHUMAN"水印字。**这两处纯版面上的重量感，是 DOM 盒子看不出来的。**

**thebrowser.company**
- hierarchy：几乎没有层级可言：整屏只有一枚居中的黑色圆形徽标，层级完全靠「细黑线条图标 vs 一整片米白色空场」的对比建立，没有字号阶梯、没有色块、没有导航。
- density：极疏（疏到近乎空白）。桌面图是整幅米白色，中心一枚约百来像素的徽标，其余全是空场。
- legibility：没有正文，因此不存在「发灰的正文」问题；唯一可读文字是徽标环形上的小号大写字母，字很小并且沿圆弧排布，且字母与线条轻微叠压。
- notable：肉眼看到的是一张「未进入内容的开场态」：里面没有任何导航、标题或卡片，只有一枚小 logo 悬在大片米白里。**这种「满屏留白 + 单一标记」的视觉重量分布是 DOM 度量完全看不到的（度量会报告有导航/有内容，但眼睛看到的是空场）。**

**vercel.com**
- hierarchy：靠「黑白极限对比 + 超大紧字距标题」建立：整个页面基本只有黑与白，层级全靠字号断崖和一枚巨大的实心黑三角作为视觉锚点，没有卡片、没有边框分区、没有色块。
- density：疏。桌面 hero 一屏只有三小块短文本＋中央一枚大三角，之后是很大的段间距与整幅浅灰描边的产品截图面板；没有卡片列表，也没有表格。
- legibility：小字明显偏灰：导航与页脚、合作方 logo 行、hero 右侧两行说明、功能清单都是很小的浅灰字，对比偏弱；大标题为纯黑、极清晰。
- notable：肉眼可见两处明显的「空」：一是页面下半部整段只留一块大面积纯白，几乎没有内容承接；二是**合作方 logo 行里有一个 logo 渲染成一个带边框的空框（框内文字几乎看不清）**。此外三角下方有一圈柔和的径向光晕，视觉重心落在这枚居中的大三角而不是左侧标题；手机端合作方 logo 条在左右两侧被裁切。

## 4. 我们自己的产物（3）

**ours-A-light**
- hierarchy：主要靠「深色加粗条目标题」+「卡片内一条高饱和绿竖条强调段」建立层级；卡片用白底+细细的浅灰边框把条目分块。
- density：中。首屏可见内容为顶栏 + 搜索框 + 一排筛选 chip + 一行数量汇总 + 一行排序，然后才进入条目；桌面正文是三列紧凑卡片（标题 / 灰色副标题 / 绿条引文 / 灰色标签行 / 页脚日期+两个文字动作）。
- legibility：总体可读，深色标题与绿条引文在近白底上对比清楚；但次级文字偏弱——副标题行、标签 pill 内文字、页脚日期明显比正文更小更浅，在整页缩略下几乎糊成一片浅灰。
- notable（最显眼的一个可改进点）：**首屏顶部的控制带太厚**——手机首屏上，条目出现之前已经堆了约 7 行（顶栏 / 数量 / 搜索 / 筛选 chips / 显示汇总 / 排序 / 分类跳转），第一张卡被推到整屏偏下；把「数量汇总 + 筛选 chips + 排序」压成一到两行，能让内容明显提前。另：每条卡片内那条绿色竖条引文在整页上形成很强的重复节奏，视觉上比标题更抢眼。

**ours-A-dark**
- hierarchy：与 light 版几乎同构，但换成「浅色底反衬」：近黑深色底，卡片是略浅的深色面，靠白色标题 + 绿竖条强调段分层；卡片之间几乎没有可见边框。
- density：中，与 light 版一致。
- legibility：正文主体可读；明显偏弱的是次级文字——灰色副标题、标签 pill、日期落在深色底上，看起来比 light 版更暗更小。
- notable（最显眼的一个可改进点）：整页是一整块深色底，而每条内的高饱和强调色被拉成整行整行的文字，缩略视图下整屏呈现大面积相近明度的色块，强弱信息区分比 light 版更难看出；建议让深色底与卡片面之间留出更明确的明度/描边差，或收窄强调色文字的行长占比。**另：深色仅覆盖正文区，页面顶部仍是浅色顶栏与浅色搜索/筛选控件，形成上浅下黑的割裂带。**

**ours-rows**
- hierarchy：同样以「深色加粗模型名 + 卡片内绿色竖条强调段」为最强视觉抓手；与 light 版的差别是标题下方多出一排数字序号跳转 chip（① 完全免费 / ② 免费额度 / ③ 身份优惠 / ④ 折扣促销），成为第二层级的导航条。
- density：中偏密。因为多了一整行跳转 chip，首屏控制带比 light 版更长：顶栏、数量行、搜索框、筛选 chips、汇总行、排序行（且该行在手机宽度下被裁切，只能看到「最近更」），之后才是条目。
- legibility：与 light 版观感一致：标题与绿条引文清楚，灰色副标题、标签行、日期偏小偏浅；跳转 chip 为白底细描边+浅灰文字，属于全屏最弱的一层文字。
- notable（最显眼的一个可改进点）：**新增的跳转 chip 行排布不齐——①②③ 占满一行后 ④ 单独折到第二行，左侧留出一大片空白，和下方排序行被右边缘裁掉（「最近更」露半截、右侧还有一个深色按钮被切）叠在一起，首屏顶部出现明显的留白失衡与被截断控件**；把跳转 chip 改成可横向滚动且等宽、或让排序行换行而非裁切，会立刻改善秩序感。

## 5. 横向观察：眼睛看得出来、度量看不出来的四类东西

1. **「空」与「占位」会被度量当成内容**：stripe 有多块纯白/极浅灰空白矩形撑起版面高度；superhuman 手机首屏有近半屏空白深紫；linear 桌面最上方是一大片纯黑空场；
   toolify 桌面左栏推广位与正式列表**长得几乎一样，肉眼分不出付费位**。→ 以 DOM 盒子算「内容面积/页高」在这些站上会失真。
2. **截图本身可能是拼接产物**：openrouter 的整页截图里同一屏列表重复三次、之间夹纯白。→ **整页截图高度 ≠ 真实内容长度**（这条直接影响所有以整页高度为口径的跨站比较）。
3. **首屏第一印象常被浮层抢走**：appsumo 首屏重心是促销弹窗；futuretools 桌面首屏被订阅浮层压住、而手机首屏没有 —— 同一个站两端给人的第一印象不是一个站。
4. **纯装饰的体量可以很惊人**：futurepedia 两组紫粉渐变缩略图、taaft 的巨型窄体标题、appsumo 手机端那枚巨大黑色数字、raycast 的键盘键位图与 3D 渲染、ai-bot 的四块马卡龙瓷砖与两条广告条。

## 7. 复核是怎么做的（可复跑）

```bash
npm run build && node scripts/serve.js --dir=dist      # :8080
node scripts/tools/check-mobile-chrome.js               # 390px 逐控件量裁切 + 亮/暗底色
```

走访查出结论之外，这次复核还暴露了**门禁的一个盲区**并补上了工具：
`verify-site.js` 只断言**页面级**没有横向溢出（`documentElement.scrollWidth === clientWidth`），
而控件被父容器 `overflow:hidden` 裁掉一截时页面级宽度可以完全正常——**门禁全绿，肉眼却看得见被裁的控件**。
`scripts/tools/check-mobile-chrome.js` 就是补这个盲区的：逐控件量
`width / scrollWidth / clientWidth / clipped` 与相对父、相对视口的越界量，并输出 `#jumpNav` 的折行情况。
