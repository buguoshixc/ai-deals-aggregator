## 二、先分析 IA：为什么最后选了「静态落地页」这条路

### 2.1 现有首页的信息架构（改之前）

```
顶栏（logo / 主题 / 统计）
  └─ .topin      58px   品牌 + 「30 条优惠 · 更新 2026-09-29」+ 主题切换
筛选区
  └─ .facets     36px   13 个 facet 按钮（分类 / 学位 / 国内 / 免费 / 收藏…）—— 横向滚动
  └─ .fbar       41px   搜索框 + 排序 + 卡片/列表视图切换
结果区
  └─ .grid 起点 196px   50 张卡（3 列），按 4 个力度档分带
```

这是一台**筛选器**：用户必须先知道「我要什么」才能把条件翻译成按钮。真实使用场景是
「我是学生，想找能白嫖的」——而首页上没有「学生」这个词的入口（`student` 只在
分类页 `/student/` 里，那页本身就不在首页上有明显入口）。

### 2.2 三条硬约束把方案空间压得很小

1. **「URL 可分享」+ 「无 JS 可读」在首页上不可兼得。**
   首页是纯静态文件，**不能按 query string 产出不同内容**。`?need=free-api` 这种写法，
   分享出去别人打开的是「首页」而不是「免费 API 结果」，爬虫读到的也是首页——两条要求同时落空。
   → **只有「每个需求一条静态路由」能同时满足这两条。**

2. **不能复制业务判断。** v1.1 已经把「谁是学生优惠」这件事收进 `audience.js` 一处；
   如果 v1.2 再写一套「首页按需求找」的判据，两边就会各自漂移（v1.1 期间已经踩过一次：
   同一个数字在首页与分类页不一致）。→ 新入口必须是**读同一份判据的第二张注册表**。

3. **移动端首屏已经被 chrome 占满。** 360px 下顶栏 + 筛选 + 结果条 ≈ 500px，
   800px 的视口只剩 300px 给内容。入口行每多占 30px，就少半张卡。
   → 入口的**高度**是这轮最贵的资源，比「入口有几个」更贵。

### 2.3 三个方案与取舍

| 方案 | 形状 | 优点 | 为什么不选 |
|---|---|---|---|
| **A. 首页加 need 筛选 + `?need=`** | 复用现有 facet 机制，改动最小 | 改动确实最小（1 个按钮 + 1 段过滤） | **同时违反「URL 可分享」与「无 JS 可读」**：query 不进静态产物。且 `.facetsin` 已经是横向滚动容器，再塞 10 枚会把入口变成「要横滑才能看见」——正是要求 7 要避免的 |
| **B. `/need/<slug>/` 静态落地页（选中）** | 复用 v1.1 的分类页生成器 | 唯一同时满足「可分享 + 无 JS + 移动端清晰」的形状；复用注册表 / 生成循环 / sitemap / 双 feed / 三段 JSON-LD / 构建自检 / 验收断言**一整套**机器 | 成本是多 10 个页面（构建 +694KB 产物的 2.3KB） |
| **C. 只做首页锚点** | 10 个 `<a href="#...">` 跳到首页已筛好的位置 | 几乎零成本 | **做不到**：首页没有「需求」这一维，锚点的落点会退回「按档位分带」，等于没有实现需求 |

**选 B。** 而且 A 被明确**搁置而非排期**——它的问题不是成本，是形状不对（见第七节）。

## 三、落地了什么（逐条对着需求）

### 3.1 十条注册表（判据只写一遍）

`scripts/lib/audience.js` 新增第二张注册表，形状与 `COLLECTION_PAGES` 一致，生成循环直接复用：

| slug | 入口文案 | 归属 | 判据（机器可读） | 当前条数 |
|---|---|---|---|---|
| `student-only` | 学生专享 | 学生 | `audience∋student ∨ eligibilityDetail.studentRequired===true ∨ benefitType∋student_plan` | 12 |
| `edu-identity` | 教育身份可领 | 学生 | `audience∋{education,educator} ∨ educationEmailRequired===true` | 7 |
| `no-card` | 无需信用卡 | 学生 | `claimRequirements.creditCardRequired===false`（**只认显式 false**） | **1** |
| `china-usable` | 国内可用 | 学生 | `availability.chinaUsable===true`（**不拿 region 顶替**） | 30 |
| `free-tier` | 完全免费 | 学生 | `pricingModel∈{free,freemium}`（与首页「① 完全免费」同一字段） | 60 |
| `free-api` | 免费 API | 开发者 | `benefitType∋free_api`（复用 v1.1 `freeApiSignal`） | 45 |
| `free-tokens` | 免费 Tokens | 开发者 | `benefitType∋free_credits` | 44 |
| `ai-coding` | AI Coding | 开发者 | `category==='编程开发'`（**唯一没有专门字段支撑的一项**） | **4** |
| `free-model` | 免费模型 | 开发者 | `benefitType∋free_model` | 12 |
| `dev-credits` | 开发者 Credits | 开发者 | `audience∋developer ∨ benefitType∋developer_credit`（复用 `developerSignal`） | 67 |

条数一律**按数据现算**（首页入口上的数字、页面顶部的数字、表格行数、JSON-LD 的 `ItemList` 全部同源），
所以不存在「改了数据忘了改文案」。`why` 文案里**禁止出现写死的条数**，并有断言守着
（`selftest:audience` 的 §9）——这条断言在写完的当轮就抓到 3 处我自己写死的数字。

### 3.2 生成：一个循环同时产出两类目录页

`scripts/tools/build-local.js` 里原来的 `renderCollectionPage` 泛化成 `renderDirectoryPage(spec, …)`：

- `DIRECTORY_PAGES` = 3 个分类页（`kind:'collection'`, 1 层深, `../`）+ 10 个需求页（`kind:'need'`, 2 层深, `../../`）；
- 前缀由 `depth` 推导（`'../'.repeat(depth)`）。**写错的症状是「页面能打开但所有内链 404」**，
  所以它有一条专门的断言：跟着 `../../deal/<id>/` 走一次，比对 HTTP 状态与落地页自指的 canonical；
- 每个需求页多一列「**为什么在这一页**」——把该条记录**命中的那个字段**打出来。
  这是「不复制业务判断」在读者侧的兑现：判据在数据层算，理由作为**数据**传到页面，前端不做推断。

### 3.3 入口行（首页）

`<!--PRERENDER:needs-->` 标记 → 构建期注入静态 HTML：

```
学生  学生专享12  教育身份可领7  无需信用卡1  国内可用30  完全免费60
      免费 API45  免费 Tokens44  AI Coding4  免费模型12  开发者 Credits67
开发者
```

- 全部是 `<a href="need/<slug>/">`，**零 JS 控件**（断言：`button|input|select` 计数为 0）；
- 桌面端一行 31px（**刻意压到一行**：两行会把首屏完整卡片从 9 张挤到 6 张，这个数字是实测出来的）；
- 窄屏（≤760px）换成**两套标签由 CSS 切换**：全称在窄屏折成 5 行、整块 204px，
  短标签（专享/教育/免卡/国内/免费/API/Tokens/Coding/模型/Credits）压回 2 行。
  **切换只用 CSS 媒体查询，不用 `data-short`+JS** —— 无 JS 的访客在窄屏上也要看到短标签，
  而 JS 在无 JS 时根本不会跑。两套 span 同时在 DOM 里，屏幕阅读器在桌面端读到的仍是全称。

### 3.4 与 v1.1 复用关系（要求 3 与 4）

- `student-only` / `free-api` / `dev-credits` **直接复用 v1.1 已有的信号函数**，不新写判据。

|---|---|

  这不是不知道，而是「入口清晰」与「首屏有卡」在 360px 上**无法同时满足**——

  （会违反要求 7 的「清晰」，需要重新决策，不是调参）。

## 六、诚实性红线（没有碰的地方）

- `no-card` 只有 1 条，页面就写 1 条，并明说「这是本站数字最小的一页」；
  **没有**把 79 条「来源没提支付方式」算成「不需要信用卡」；
- `china-usable` 30 条 vs 首页「国内」按钮 60 条：页面**显式解释**这不是同一件事，
  差额是「尚未确认」不是「不可用」；`unknown` 一律渲染成「尚未确认」，从不出现在否定措辞里；
- `ai-coding` 4 条：页面直说这是**数据缺口**，并说清为什么不去扫关键词凑数；
- 十条页面的 `why` 都不含版本号、不含写死的条数、不含 Markdown 记号（会原样渲染给读者）。

## 七、没做的 / 做不到的（不藏）

1. **`ai-coding` 没有字段支撑。** 数据模型里没有「是否用于写代码」。
   现在用 `category==='编程开发'` 兜着，只有 4 条。**这是 v1.3 的目标之一**：
   给采集侧加一个字段（或给 `category` 加子类），而不是在页面层放宽判据。
2. **`creditCardRequired` 全库只有 1/80 有明确值。** 「无需信用卡」这条需求的真实价值
   取决于后续把这一项采上来；现在是 1 条，就如实显示 1 条。
3. **`student_plan` 作为规范值缺席。** `audience='student'` 有 15 条（含工具），
   其中 deal 12 条 —— 与 `student-only` 的 12 条一致，但「学生套餐」这个更窄的概念没有独立值可依。
4. **`dev-credits` 67 条偏宽。** 它继承 v1.1 `developerSignal` 的宽度（开发者 67/80），
   所以它更像「开发者能用的」而不是「开发者专享额度」。这一点写在页面 `why` 里。
5. **方案 A（首页 `?need=` 筛选）没做，也没排期。** 不是成本问题，是它无法满足要求 5+6。
   如果将来要「首页原地切换需求视图」，必须先接受「URL 不可分享」或「无 JS 不可读」二选一。
6. **`/need/` 二级目录的深度前缀靠断言守，不靠人记。** 新增第 4 层目录前请先看 `DIRECTORY_PAGES` 的 `depth`。
7. **文案里的短标签是手工选的**，没有从数据推导。十条是稳定的；若将来增删入口，`short` 必须一起给，
   否则 `selftest:audience` 会红（有断言）。

## 八、下一步：是否进入 `v1.3-evidence-provenance`

**建议：进入，且把 `ai-coding` 的字段缺口并进去。**

理由三条：

1. **v1.2 的形态已经把「证据」这个需求顶到了台前。** 这轮做页面时反复要回答同一个问题：
   「这条记录凭什么是学生专享 / 凭什么说国内可用」——而现在的答案是
   `provenance` 只有 88/134 条、且**缺少字段级出处**（哪个字段来自哪个来源的哪句话）。
   十条需求页的「为什么在这一页」列已经把**字段**打出来了，但**下一层（这句话从哪来）是空的**。
   v1.3 的 provenance 正好接在这个位置上，属于顺水推舟，不是另起一摊。
2. **它是所有「多入口」的前置条件。** 入口越多，「口径可信」就越重要：
   首页 13 个筛选按钮 + 3 个分类页 + 10 个需求页 = 26 个入口都读同一批字段，
   任何一个字段的可信度不足都会在 26 个地方同时放大。
3. **v1.2 的验收机器可以直接复用。** 需求页是「生成循环 + 自检 + verify 段」的三件套；
   v1.3 若要给每条记录加「出处」页或出处列，形状完全一样，边际成本低。

**进入 v1.3 前建议先堵的一个小口子**（半小时级）：`ai-coding` 的 `category` 判据
在页面上被标注为「唯一没有字段支撑」，如果 v1.3 决定加字段，这个标注要同步撤掉，
否则会变成一句过期的自我说明。
