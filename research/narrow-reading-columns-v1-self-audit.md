## 2. 本轮**没有**证明的东西（如实登记）

1. **类名漂移（把 `.snote` 改名 / 换容器）仍然不是判据能直接看见的东西**：本轮的登记制是**针对 CSS 声明**的，
   与「页面上该有多少条说明」无关。已覆盖面仍然只有上一轮登记的那几条间接守卫
   （3 条别名页各恰好 1 条的 ③b 断言 · M1–M4 四壳必须带说明 · M15/M16 正对照 · 每页冻结串恰好 1 次）。
2. **px / rem 口径的窄列没有登记制**：`.search`（440px）· `.cmpchip`（210px）这类**控件**宽度天然窄，
   把它们纳入登记只会得到一堆噪声；真正属于「阅读列」的 px 案例（`.detail-main`）由 §22b 原有断言管着。
   本轮**没有**证明「px 侧不许出现新的窄阅读列」——只证明了「ch 侧必须有登记」。
3. **`narrow-unregistered` 只在两个桌面档 + 两个样本档判**：与其它 §22c 判据同一套视口语义；
   @390 那一档只量页面溢出（本轮未改该作用域）。
4. **居中容差 2px 没有做敏感性标定**：实测左右内边距是 **445.63px / 445.63px**（差 **0**，离容差很远）；
   但本轮**没有**去造「差 1.9px」的边界形态来钉住容差本身的选取。
5. **没有做「把登记表删空」的负例**：`entries: []` 时 dist 应立刻红（`.pdetailbody` 未登记）。
   这条推理成立（同一条扫描面），但**没有实跑**——如实记在这里，下一轮若要收紧登记制，先跑它。

## 3. 本轮被门禁自己抓出来的一个真缺陷（记录在案）

第一版扫描器把 CSS **注释**当成了选择器的一部分：页面级样式里规则前面常有一整段说明注释，
扁平正则 `([^{}]{1,200})\{([^{}]*)\}` 会把 `/* … */ .pdetailbody` 整段当作 selector ⇒
**已登记**的 `.pdetailbody` 被判成未登记，dist 上立刻 5 条红（两个桌面档 + 两个样本档 + M16 承重证明）。
修法是扫描前先剥注释（`replace(/\/\*[\s\S]*?\*\//g, ' ')`），并把这句教训写进代码注释。
⇒ 「判据写完就绿」在本轮**没有**发生：这条判据是**先红后绿**的。

## 自审补记（judge-hardening-v1a · 2026-10-08 追加，append-only）

> 追加人：`p2-residuals-engineer`（任务 t9）。**不改上文任何字**，只在这里补一条**与上文措辞不符**的事实。
> 触发来源：t5 的对抗性验证（`research/_raw/registry-adversary-v1/findings.json` 的 **R11**）。

**上文与本轮报告里关于 §19 几何的口径，强于当时的实现能兑现的强度。** 具体是：

1. **本轮报告把 §19 的几何承诺写成了「登记的窄列必须居中且真的比容器窄」** —— 这句话在**实现**上
   只对 `WIDE_NARROW_ENTRIES[0]` 成立：`verify-site.js` 的 §19 当时写的是
   `const entry = WIDE_NARROW_ENTRIES[0] || { … .pdetailbody … }`。
   **第二条及以后的登记项，一条几何都没有量过。**
2. **幽灵条目（在任何产物页面里都不存在的选择器）当时完全不报**：登记表里写一个 `.ghost-nowhere`，
   既不量、也不报「找不到」，`entries` 的「机器可读清单」因此可以在**一半是假的**情况下继续全绿。
3. **`entries: []`（清空登记表）当时会静默回落到一个隐式默认**（`.pdetailbody { max-width: 72ch }`）——
   也就是说「清单为空」与「清单里恰好写着这一条」在读数上不可区分。这是一条**没有断言的空窗**。
4. **t5 的实测**（judge-hardening-v1a 复现）：登记 `[.pdetailbody, 未居中的 .page-notes-summary, .ghost-nowhere]`
   并在产物里真写入未居中的 70ch 窄列 ⇒ **整轮 874 项 / 0 失败（全绿）**。

**修法（judge-hardening-v1a / t9，已落地）**：§19 改为**逐条遍历**登记项 —— 每条都要
「真的在产物里命中 + 比容器窄 ≥ 40px + 左右内边距差 ≤ 2px + 自身不裁切（横竖都算）」；
幽灵条目 ⇒ 红；`entries: []` ⇒ 显式声明「本轮没有几何对象」（删掉隐式回落）。
本轮另加一条 **生效宽 ÷ 声明 ch 的现场换算值 ∈ [0.8, 1.2]**。
读数：`verify-site.js --dir=dist` = **881 项 / 0 失败**（基线 880，+1）。

**这条补记的意义**：轮 2 的「§19 覆盖了保留窄列」这句话，**在当时的产物上是对的**
（登记表恰好只有一条），但**在承诺层面是过强的** —— 它没有说清「覆盖」= 只有第一条。
本补记把它改写成与实现一致的强度：**当时只对 `entries[0]` 成立；幽灵条目不报；空清单不留断言。**
