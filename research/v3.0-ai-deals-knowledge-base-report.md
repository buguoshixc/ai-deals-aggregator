## 2. 总体架构决策

1. **分层不合并**（详见 `docs/SCHEMA-v3.0.md` §0）：真值层（三份数据 + 三份日志，字段集**一个都没改**）·
   人工来源层 · 索引层（`models.json` 只回答身份）· 关系层（`model-registry-links.json` 显式映射）·
   归档层（**不落新真值文件**，由 `baseline + events + absence + tombstone` 派生）· 出口层（`/data/index.json`）。
2. **判据只有一处**：模型身份 / 厂商门槛 / 归档状态 / Manifest 数字各一个模块；
   页面、Feed、自测、门禁全部调用它，不许有第二份实现。
3. **URL 策略选方案 A**：继续用 `/vendor/<slug>/`，**不新增 `/provider/`**
   （理由：9 个既有厂商页已达标且 slug 来自显示名，方案 B 会把 9 条 URL 变 noindex 换 0 条新信息）。
4. **数字可重算**：页面计数一律带 `data-*` 标记，构建期**从盘上现读**再对账。
5. **不替用户做判断**：不做推荐 / 排序 / 星级 / 成本计算器 / 跨币种或跨单位换算。

## 6. Model Registry

### Schema / ID / Alias / Mapping / Candidate Policy
完整契约见 `docs/SCHEMA-v3.0.md` §1 / §2。要点：

- **Schema**：来源层 `scripts/data/models.json` 是 `{slug: entry}`，派生字段表明确列出（`id` / `firstSeen` / `lastSeen` /
  `registryModelId` / `updatedAt` / `count`），**手写即红**。
- **ID**：`sha1('model|' + slug)[:12]`；slug 是人的决定，改 slug 即换身份。
- **Alias**：原文**精确匹配**，不归一、不做相似度（本仓有 `/krea/i` 命中 `Kreado AI` 的实测教训）。
- **Mapping**：**64 条**显式映射（API 55 + Coding 9；Coding 侧的 `trae / DeepSeek-Flash → deepseek-flash` 是 v3.0 修订新增，见附录 A），
  每条必须指向真实存在的 `apiPlanId`/`modelKey`/`planId`/`modelName`/`registrySlug`。
- **Coverage（v3.0 修订）**：`scripts/data/model-registry-gaps.json` 是关系层的补充 —— 套餐侧那些
  **不对应单一模型身份**的模型串（`pool` / `series` / `multi-model` / `off-registry-model` / `non-text-resource`）
  逐条登记理由。它不发布、不写 `registrySlug`；`validatePlanModelCoverage()` 规定
  「既没映射也没声明」**即红**（构建期 + 三支检查工具四处都停）。
- **Candidate Policy**：未映射只能进候选与报告；**没有任何「工具自动写生产映射」的路径**。
  候选由规则算出（API 侧 `candidatesOf()` · 套餐侧 `planCandidatesOf()`），与关系层无关 ——
  所以"能精确对上却没写映射"这件事会被规则自己顶出来，不靠人凭印象去挑。

### A.6 独立审查（2026-10-02）与它抓到的两个洞

这一轮改完先跑了一遍**独立的对抗式审查**（另一个 agent，只读 + 自己写变异探针，**不改被审的文件**，
结论 `pass`：0 blocker / 0 high / 0 medium）。它没能证伪映射的合法性、10 条声明的诚实性、
"只增不减"、以及站点产物；但它抓到两个**真的洞**，两个都当场修掉并补了牙：

| # | 洞 | 为什么是真问题 | 修法 |
|---|---|---|---|
| F1 | `validateGaps()` / `validatePlanModelCoverage()` 都**不接收 registry 表**，于是把一条**归一后能精确落到某个 registry 身份**的串（探针用真实别名 `zai-org/GLM-5.3`）声明成"不对应单一模型身份"时，两个 lib 级判据**都不响** —— 只在本文件的"漏网之鱼"检查里响，**硬门禁工具本身照不到** | 声明表本可以拿来**绕过映射**，而这是本层最该防的作弊路径 | `validateGaps()` 增判据：用 `normalizedIndexOf(table)` 反查，命中即红；并且**调用方必须传表**，不传（table 为空）却有声明 ⇒ 红（判不了就不是通过）。8 个调用点全部改为传表；新增【牙 #22】两条夹具 + 变异电池 **#24**（走 `check-model-registry-links.js` 端到端） |
| F2 | `model-registry-gaps.json` 的 `_rules` ⑥ 写着 note「不许写成引文」，而实际 10 条 note 里都有 `「…」` 引用 —— 规则与文件自相矛盾且无人执行 | 自相矛盾的规则会让下一个人以为"引用违规"，也可能反过来被当成"引文不重要" | 规则改成**它真正要求的**：引用官方原文时必须**逐字来自该套餐记录自己已有的文字**（不许新造引文）。审查员已逐条把 10 条 note 里的引用与该套餐记录对照过：**全部逐字一致**，没有制造第二事实来源 |

另外一条 informational（F3）：`DeepSeek-Flash` 那条映射用的是"归一后相等"这支**候选**规则，
而模块注释里写着"归一化只用于候选与搜索，生产身份一律精确相等"。审查员判定**站得住**
（等的是 registry 自己声明的 `canonicalName`，只差大小写写法），但提醒它是**人工判断**。
据此把那条 note 的措辞改成明说"**人工判断（explicit-mapping）**"，不再让读者以为是把候选规则当判据用。
