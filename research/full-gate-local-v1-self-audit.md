# full-gate-local-v1 自审（对抗性自查）

> 对象：`research/full-gate-local-v1-report.md` 与它的 6 份小 JSON。
> 这是**验证类**任务的自审：重点不是「我跑了吗」，而是「我跑出来的读数能证明什么、不能证明什么」。

---

## 1. 我可能弄错的六件事（每条给反证或明确承认边界）

### 1.1 「51 步」——如果 `- name:` 出现在注释或字符串里，运行器会多算

运行器（上一轮 scratch 里的 `full-gate.cjs`）用 `/^\s*- name:\s*(.+)$/` 逐行扫 `action.yml`，
所以锚定行首（含缩进）的 `- name:` 才算，正文行里出现这四个字不会命中。

**独立反证**：CI 原始日志里复合 action 内部的 `Run` 组**也正好 51 个**（第 14–64 组）。
两边是两套互不相干的读取方式（一边读 YAML 文本、一边数 GitHub 打印的组），得到同一个数。

### 1.2 「跳过 3 步」的依据是正则启发式（承认）

判定是「该步 `run` 体里有没有 `${{ }}` / `GITHUB_OUTPUT` / `GITHUB_STEP_SUMMARY` / `install --with-deps`」。
我逐条打印了命中的 token（报告 §3），并确认这 3 步在 CI 日志里**都真实存在且 pass** ——
也就是说它们不是「运行器凭空认为该跳」。

**承认的洞**：若某一步在**注释**里写了 `${{ }}`，运行器会把一个本该本地执行的步骤跳过，
而**这一步不会变红**（跳过不判失败）。本次 48 条执行的都通过，没有出现「该跑却被跳过」的证据，
但**没有独立于该启发式的第二判据**。

### 1.3 「CI 51/51 全过」的依据是日志里 0 个 `##[error]`（承认）

这不是「每一步都退出码 0」的强证明：某一步可能内部吞掉错误、或 CI 的 shell 用的是
`set +e`（日志里第 60 组正是 `set +e`）。**反证的一半**：job 结论是 `success`，
且各工具自己的汇总行都是「0 失败」（selftest / seo-verify / verify-site / check:ci）。
**承认的一半**：我没有独立于该日志的第二来源去判定 CI 每一步的真实退出码。

### 1.4 「Gate 不改产物」——我的 before 是**手工构建**的，不是「上一次 Gate 跑完的 dist」（这条最重要）

我的对账是：`手工 build → digest-before` vs `Gate 跑完（含第 36 步重建）→ digest-after`，两者逐文件相同。

它能证明的：
- **Gate 的最终产物 = 同树同命令的构建产物**（两次独立构建逐字节相同）；
- **第 36 步之后到第 51 步之间没有任何步骤改动 dist**。

它**不能**证明的：第 1–35 步里如果有步骤改了 dist（哪怕只是写了个临时文件），**会被第 36 步的重建覆盖**，
我从头到尾看不出这个改动。⇒ 更严格的写法应该是「产物**最终态**与同树构建态逐字节相同」。
报告里我把结论写成「Gate 不改产物」，措辞比证据更强了一格；**这里如实降级**：
证据支持的是「Gate 跑完后的产物与同树构建产物逐文件相同」。

### 1.5 「+6 来自 PR #63」——这是**归因**，不是逐条 diff

三条支撑：(a) `git log 4b366d2..95dfeb9 -- scripts/tools/verify-site.js` 只有 `0a1fe92`（#63）；
(b) 该轮报告自己记「master `4b366d2` = 874 ⇒ 本轮 880（+6）」；(c) 同树 CI 对照（880/886 两边一致）。

**承认**：我没有把 `4b366d2` 版本的 `verify-site.js` 拿出来对同一份 dist 跑一遍（那才是逐条 diff 级证据）。
所以「+6 全部来自新加的那 6 条」是**由作者记录 + 提交归属推出的**，不是我自己重算的。

### 1.6 「同树同读数」只覆盖 5 个口径

我比的是 5 条汇总读数（check:ci / build 门禁 / seo-verify / verify-site / --compare）+ seo-selftest + fitness。
**其余 44 步的逐步读数没有做同树对照**（CI 日志里有，但我没有逐条抽出来比）。这不是「一致」的反例，
但「逐条对齐」这句话的强度只到这里：**结构逐条（51↔51、0 冲突）、读数抽样（7 条）**。

## 5. 如果重来一次，我会改的三处

1. **产物对账改成三段**：`手工 build（before）→ 只跑到第 36 步 → digest(mid) → 跑完余下 15 步 → digest(after)`。
   这样才能把「构建期之后没人动产物」与「第 1–35 步没动产物」分开证明（现在只能证明后者之外的那半步）。
2. **给 CI-only 判定加第二判据**：例如要求被跳过的步骤同时满足「`action.yml` 里该步所在 job 有 runner 级上下文」
   或「该步的输出被后续步骤引用」，而不是只看 `run` 体。
3. **把 CI 侧日志按命令文本做二级匹配**（而不只是按顺序配），这样「51↔51」就不依赖顺序假设。
   并且把 **44 条未抽样的逐步读数**也做成同树对照表。
